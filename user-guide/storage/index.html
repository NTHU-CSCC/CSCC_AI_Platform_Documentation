    Storage¶

    A storage volume is a folder that outlives your workspaces.

    A workspace with no volume keeps nothing

    Personal storage mounts at /home/<your username>; each group volume mounts at /mnt/shared/<volume name>. Files saved anywhere else are lost when the workspace stops, restarts or is deleted. The platform warns you before starting a workspace with no volume.

    Who can use it: an admin creates personal storage, so not every account has it; if the My Storage tab is missing, ask an admin. Group admins manage who can use group volumes; only current members can hold permissions.

    Storage types¶

    Personal storage Group storage
    Owner You A group
    Created by Admin Admin, on request
    Who can use it You only Group members, by permission
    Best for Your datasets, notebooks, experiments Shared datasets, team work
    Managed from My Storage tab Group Storage tab

    Storage page¶

    Figure 1: The Storage page with the My Storage and Group Storage tabs.

    • My Storage — your volume as a card with the file browser status (Stopped, Starting, Running, Stopping, Error), a usage bar and the file browser buttons.
    • Group Storage — your groups' volumes in a table: name (with its group underneath; hover for the created date), status (Active is ready to mount, Terminating is being removed, Missing means the platform can't find it; the file browser's state shows below unless it is stopped), usage against capacity (for example 12 / 50 Gi; just the size until usage is measured), your permission, and action icons. The action icons stay at the right edge even when a narrow screen makes the table scroll.

    Stopping a workspace doesn't unmount a group volume; it is released only when an admin removes it from the project or deletes it.

    If the file browser shows Error, click Start FileBrowser (for a group volume, the icon in Actions) to restart it. Your files are not affected.

    Usage bar¶

    The bar reads used / total Gi with a percentage. It turns amber at 70% and red at 90%.

    Capacity is the space you were given; Usage is what you have written. A dash (—) means not measured yet, not empty. Numbers refresh every few minutes.

    Volume lifecycle¶

    1. You ask for storage on the Requests page.
    2. An admin approves and creates the volume.
    3. The volume is attached to a project and appears in the workspace form.
    4. Your workspaces, jobs and deployments mount it; data survives restarts.
    5. An admin deletes it, and the data is gone.

    Deletion is permanent

    Deleting a volume erases everything in it. Back up first.

    Browse files¶

    1. On the My Storage tab, click Start FileBrowser and wait until the badge shows Running.
    2. Click Open FileBrowser. It opens in a new tab.
    3. When you're done, click Stop FileBrowser.

    For a group volume, use the Actions icons: Start FileBrowser, Browse, Stop FileBrowser. They are hidden if your permission is None.

    Figure 2: The file browser, with upload, download and delete.

    The file browser opens folders, uploads, downloads, creates folders and deletes. Deleting is immediate.

    Large uploads

    Don't upload files over 500 MB through the browser (size and timeout limits). Download them inside a workspace with wget, curl or rclone.

    Mount storage in a workspace¶

    1. In the New Workspace form, open Storage Volumes; it lists your personal storage and the group volumes attached to the chosen project.
    2. Tick the volumes you want.
    3. Click Start.

    Permissions¶

    Each group volume has a permission for each user:

    Permission What you can do
    Read Mount and read
    Write Mount, read, and write
    None Nothing. You can't mount or browse it

    None set by a group admin beats anything the project or group would give you; clear it and your normal permission returns. Ask your group admin to change permissions; they can bulk-edit on the group's Storage tab (see Groups).

    Only group managers and admins can open the permissions page; for everyone else the Permissions icon returns to the Storage page.

    Your permission applies to everything you run. Without permission, a job or deployment can't mount the volume even if its YAML names it, and a volume not attached to the project can't be mounted from it at all.

    Read-only means read-only. With Read, the volume is mounted read-only in every workspace, job and deployment; readOnly: false in your YAML is reset. Project and group managers are no exception.

    Separately, jobs and deployments you start from a config file mount group volumes read-only for ordinary project members even with Write; project and group managers skip that rule, but not their own Read.

    Ask for more storage¶

    Only platform admins create group volumes. To get one, or more space:

    1. Go to Requests → + New Request.
    2. Pick type Resource.
    3. Say what you need: size, purpose and group name.
    4. Click Submit. An admin reviews it and creates the volume.

    Common questions¶

    My volume shows Pending. When can I use it?

    It is still being created, usually under a minute. After 5 minutes, contact an admin.

    My volume is full but I see no large files.

    In a workspace terminal, run du -sh /home/<your username>/*. The usual culprits are hidden folders such as .cache and .local, and notebook checkpoints.

    The usage bar shows a dash.

    Not measured yet. Check in a few minutes; if still blank after an hour, contact an admin.

    I deleted files but the usage bar has not moved.

    Numbers refresh every few minutes. Wait, then reload.

    I see a group volume but cannot browse it.

    You need at least Read on it. Ask your group admin.

    Is my data still there after I delete a workspace?

    Yes, unless the volume itself is deleted.

    Can several workspaces mount the same volume?

    Yes.

    Files I uploaded in the browser do not show in my workspace.

    Look under /home/<your username> (personal) or /mnt/shared/<volume name> (group). New uploads show up right away; no restart needed.
