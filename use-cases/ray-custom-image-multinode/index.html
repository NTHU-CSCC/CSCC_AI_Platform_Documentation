    Run one NCCL job on GPUs in several machines with your own Ray image¶

    vLLM's data-parallel mode and most multi-GPU PyTorch code need PyTorch and NCCL on every Ray worker, and often more GPUs than one machine holds. The platform's Ray image has no PyTorch. With the X-CSCC-Image header your Ray session runs an image you built instead, and its workers can land on different machines. In the run below, three RTX 5090 workers on two machines formed one NCCL group and reached 0.74 GB/s all-reduce bus bandwidth.

    In this post you build a Ray image with PyTorch and vLLM, then run an NCCL all-reduce across machines from your laptop. By the end you have:

    • An image in your project that Ray sessions can use
    • A Ray session whose workers run that image on more than one machine
    • A measured NCCL bandwidth between them

    The commands and output below come from a run on the platform on 2026-10-06.

    Prerequisites¶

    • VPN access, the Manager role in a project that has Image Build Permission, and an API token (Settings)
    • cscc-cli and the Root certificate from Settings → Security → Downloads
    • Python 3.10 or later on your laptop
    • A queue that allows 3 or more GPUs in your project
    • About 45 minutes, most of it the first image build

    What you'll build¶

    Part Where it runs What it does
    ray-vllm image Your project's registry Ray 2.58.0, PyTorch 2.9, vLLM 0.11.2
    ray command Your laptop Uploads the folder, sends the job, shows the output
    Ray session The platform Head and workers run your image; one GPU per worker
    allreduce.py The workers One NCCL rank per GPU, times all-reduce

    Step 1: Write the Dockerfile¶

    Save this as Dockerfile in an empty folder:

    FROM rayproject/ray:2.58.0-py311-gpu

USER root
RUN apt-get update -y && \
    apt-get install -y --no-install-recommends ibverbs-providers && \
    rm -rf /var/lib/apt/lists/*

USER ray
RUN pip install --no-cache-dir "vllm==0.11.2" "ray[default]==2.58.0"

    ① The Ray version must be 2.58.0, the same as the platform's Ray sessions. ② End as USER ray. Workers run as UID 1000, which is ray in this base image. ③ ibverbs-providers lets NCCL use the RDMA network when an admin turns it on for your project. Without it NCCL uses TCP.

    If the build fails:

    Error Fix
    external Dockerfile frontend is not allowed Delete the # syntax= line
    must be a regular file or directory Replace symbolic links in the folder with copies
    Dockerfile RUN instruction uses a disallowed flag Remove --mount=type=cache, secret or ssh from RUN lines

    Step 2: Build the image¶

    cscc-cli build --project <project id> --name ray-vllm --tag 2.58.0-vllm0.11.2 .

    When the build is queued, cscc-cli prints the image's destination. In this run:

    Destination: 192.168.110.1:30003/p26000001/ray-vllm:2.58.0-vllm0.11.2

    The build took about 20 minutes, most of it downloading PyTorch and vLLM, and the image is about 11 GB. A rebuild that keeps the same base image and packages reuses the cached layers.

    Step 3: Set up your laptop¶

    Install Ray, trust the platform's Root certificate, and name your image in the headers. Submit a job explains each line.

    pip install "ray[default]==2.58.0"
export REQUESTS_CA_BUNDLE=~/Downloads/cscc-root-ca.pem
export SSL_CERT_FILE=~/Downloads/cscc-root-ca.pem
export RAY_JOB_HEADERS='{"Authorization":"Bearer cscc_xxx","X-CSCC-GPUs":"3","X-CSCC-Queue":"<queue>","X-CSCC-Image":"<destination from step 2>"}'
export RAY_ADDRESS=https://api.cscc.nthu.edu.tw/api/v1/projects/<project id>/ray

    For 8 GPUs, set "X-CSCC-GPUs":"8" and run the script with --gpus 8.

    Step 4: Write the all-reduce test¶

    Save this as allreduce.py in a new empty folder:

    """Measure NCCL all-reduce bandwidth across GPU workers on several machines."""
import argparse
import os
import socket
import time

import ray


@ray.remote(num_gpus=1)
class Rank:
    def endpoint(self):
        with socket.socket() as s:
            s.bind(("", 0))
            port = s.getsockname()[1]
        return ray.util.get_node_ip_address(), port

    def run(self, rank, world, addr, port, mib, iters):
        import torch
        import torch.distributed as dist

        os.environ.update(MASTER_ADDR=addr, MASTER_PORT=str(port))
        dist.init_process_group("nccl", rank=rank, world_size=world)
        x = torch.ones(mib * 1024 * 1024 // 4, device="cuda")
        for _ in range(3):
            dist.all_reduce(x)
        torch.cuda.synchronize()
        start = time.perf_counter()
        for _ in range(iters):
            dist.all_reduce(x)
        torch.cuda.synchronize()
        seconds = (time.perf_counter() - start) / iters
        dist.destroy_process_group()
        with open("/proc/sys/kernel/random/boot_id") as f:
            machine = f.read().strip()[:8]
        busbw = x.numel() * 4 * 2 * (world - 1) / world / seconds / 1e9
        return rank, machine, torch.cuda.get_device_name(), seconds * 1e3, busbw


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--gpus", type=int, required=True)
    parser.add_argument("--mib", type=int, default=256)
    parser.add_argument("--iters", type=int, default=20)
    args = parser.parse_args()

    ranks = [Rank.remote() for _ in range(args.gpus)]
    addr, port = ray.get(ranks[0].endpoint.remote())
    rows = ray.get([r.run.remote(i, args.gpus, addr, port, args.mib, args.iters)
                    for i, r in enumerate(ranks)])
    for rank, machine, gpu, ms, busbw in sorted(rows):
        print(f"rank {rank}  machine {machine}  {gpu}  {ms:7.1f} ms  {busbw:5.2f} GB/s")
    print(f"machines: {len({r[1] for r in rows})}, GPUs: {len(rows)}, "
          f"all-reduce {args.mib} MiB bus bandwidth: {min(r[4] for r in rows):.2f} GB/s")

    ① @ray.remote(num_gpus=1): one actor per GPU, so Ray starts one worker for each rank. ② Rank 0's address and an unused port become the NCCL rendezvous point. ③ boot_id is the same for workers on the same machine, so the number of distinct values is the number of machines.

    Step 5: Submit the job¶

    ray job submit --working-dir . \
  --runtime-env-json '{"env_vars":{"NCCL_DEBUG":"INFO","NCCL_DEBUG_SUBSYS":"INIT,NET"}}' \
  -- python allreduce.py --gpus 3

    The first job on a new image waits while each machine downloads it once, about 2 minutes per machine in this run. While that happens, ray job submit can stop early:

    Message What happened Do this
    Failed to connect to Ray at address The cluster was not ready within 2 minutes Run the same command again
    WebSocket connection closed unexpectedly with close code 1006 The job was accepted, but the output stream dropped while workers started The job keeps running; follow it with ray job logs <job id> and ray job status <job id>

    In this run the stream dropped after 2 min 23 s. The job succeeded 173 s after it was submitted. On a cluster whose workers were already up, the same job took 24 s.

    Step 6: Read the results¶

    rank 0  machine 513bdbb4  NVIDIA GeForce RTX 5090    480.6 ms   0.74 GB/s
rank 1  machine 513bdbb4  NVIDIA GeForce RTX 5090    480.6 ms   0.74 GB/s
rank 2  machine 9e293410  NVIDIA GeForce RTX 5090    480.6 ms   0.74 GB/s
machines: 2, GPUs: 3, all-reduce 256 MiB bus bandwidth: 0.74 GB/s

    ray job status raysubmit_8X3jDzUBBWqFXkw3 reported SUCCEEDED.

    The NCCL lines show how the ranks talk:

    NCCL INFO NCCL version 2.27.5+cuda12.9
NCCL INFO NET/IB : No device found.
NCCL INFO Channel 00/0 : 0[0] -> 1[0] [receive] via NET/Socket/0
    • Two ranks shared one machine and the third was on another, all in one NCCL group.
    • via NET/Socket means TCP. Ranks on the same machine also use it, because each worker is separate.
    • 0.74 GB/s bus bandwidth for 256 MiB; one all-reduce took 0.48 s. Across runs this ranged from 0.58 to 0.74 GB/s, and setting NCCL_SOCKET_NTHREADS=4 and NCCL_NSOCKS_PERTHREAD=4 did not raise it, so keep the defaults.

    Each worker reserves one GPU and 16 GiB of memory. In an earlier try with 4 GPUs, the fourth worker waited because the only machine with a free GPU did not have the memory, and the script waited with it. Before you submit, check the free GPUs in GPU Cluster Status on the dashboard's home page. To use fewer GPUs, pass a smaller --gpus; to lower X-CSCC-GPUs, end the session first.

    Step 7: End the session¶

    To release the GPUs now, open the project's Ray tab and select End session under Ray sessions.

    What you built¶

    A Ray session that runs your own image on GPUs in several machines, with a measured NCCL baseline. To use it for your own work:

    • Put the packages you need (PyTorch, vLLM) in the image and upload your code with --working-dir, so code changes need no rebuild. Start one rank per GPU as allreduce.py does.
    • For vLLM data parallel on Ray, keep model weights in your group storage (/mnt/shared/<volume name>/...) so every worker reads the same path.
    • Pin the image by tag in X-CSCC-Image and change the tag when you rebuild; a running session keeps the image it started with.
    • Plan for 0.6 to 0.7 GB/s between workers over TCP: a 256 MiB all-reduce takes about half a second. Jobs that exchange that much every step spend most of their time on the network.
