    Build your own image from your laptop¶

    The platform's images cover the common frameworks, but sooner or later a project needs one more library, a pinned version, or your own code baked in. You don't need Docker on your laptop for that. cscc-cli build uploads your folder, the platform's build engine builds it, and the image lands in your project's private registry, ready for a config file.

    In this post you build the image that the two-GPU training and GPU desktop posts use. By the end you have:

    • cscc-cli installed and signed in on your laptop
    • An image with PyTorch, TensorBoard, Matplotlib and your scripts, in your project's registry
    • The image reference to put in a config file

    The commands and output below come from a run on the platform on 2026-10-04.

    Prerequisites¶

    • VPN access, and the Manager role in a project that has Image Build Permission
    • An API token (Settings)
    • About 15 minutes

    What you'll build¶

    Part Where it runs What it does
    cscc-cli Your laptop Packs the folder, uploads it and follows the build log
    Build engine The platform Runs the Dockerfile; one build at a time for everyone
    Project registry The platform Keeps the image, visible only to your project

    Step 1: Install cscc-cli¶

    Sign in to the dashboard and open Settings → Security → Downloads (details). Download the file for your system, then on Linux:

    chmod +x cscc-cli-linux-amd64
sudo mv cscc-cli-linux-amd64 /usr/local/bin/cscc-cli

    On macOS use the darwin file; on Windows, see Install. The CLI already trusts the platform's certificate.

    Sign in with your token and check who you are:

    cscc-cli login --api-url https://api.cscc.nthu.edu.tw --token cscc_...
cscc-cli whoami

    login prints where it saved the token, and whoami prints your username and role.

    Step 2: Write the Dockerfile¶

    Make a folder with the Dockerfile and the two scripts it copies, train_ddp.py and plot_runs.py:

    ddp-trainer/
├── Dockerfile
├── train_ddp.py
└── plot_runs.py

    FROM pytorch/pytorch:2.14.1-cuda13.0-cudnn9-runtime

# X11 and Tk so the plots can open in a GPU desktop
RUN apt-get update \
 && apt-get upgrade -y \
 && apt-get install -y --no-install-recommends libx11-6 libxext6 libxrender1 libxft2 python3-tk xterm fonts-dejavu-core \
 && rm -rf /var/lib/apt/lists/*
# The image's Python is system-managed (PEP 668)
RUN pip install --no-cache-dir --break-system-packages tensorboard==2.20.0 matplotlib==3.10.7

COPY train_ddp.py plot_runs.py /app/
WORKDIR /app

    ① apt-get upgrade -y pulls in the base image's security fixes, so the security check that runs before the image's first start is less likely to block it. ② This base image marks its Python as system-managed, so pip needs --break-system-packages. Without it the build stops with externally-managed-environment. ③ Install everything at build time. A running container can't apt-get install.

    Step 3: Build¶

    From inside the folder:

    cscc-cli build --project <project id> --name ddp-trainer --tag v1 .

    The build took 9 minutes. The 3 GB base image was already in the build engine's cache from an earlier build; the first build on a new base image also pulls it. The build engine shuts down when idle, so after a quiet spell the first build waits about a minute for it to start.

    Step 4: Use the image¶

    The Destination line is the image reference. Put it in a config file's image: field:

    image: 192.168.110.1:30003/p26000001/ddp-trainer:v1

    Train on two GPUs with a config file deploys exactly this.

    What you built¶

    An image built on the platform from your laptop, with no local Docker, stored where only your project can pull it. Next time:

    • Change the Dockerfile and build again with a new --tag; keep the old tag for configs that still use it.
    • Pass build-time values with --build-arg KEY=VALUE (details).
    • Run cscc-cli build --follow=false to submit and close the terminal; the dashboard keeps the build history.
