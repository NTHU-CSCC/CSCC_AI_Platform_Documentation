    Train on two GPUs with a config file¶

    A training run that fits in a workspace notebook rarely stays there. Once the script works, you want it to run unattended, on more than one GPU, with its results kept. A config file does that: a few lines of YAML that the platform schedules as a job, with your storage mounted and as many GPUs as your plan allows. In the run below, PyTorch DistributedDataParallel (DDP) on two RTX 5090s trained ResNet-18 1.4 times faster than one GPU, to the same accuracy.

    In this post you train ResNet-18 on CIFAR-10 with DDP, first on one GPU, then on two. By the end you have:

    • A DDP training script that uses every GPU the job gets
    • A config file you deploy from the dashboard, once per GPU count
    • TensorBoard logs and checkpoints in your storage, and a measured comparison

    The commands and output below come from a run on the platform on 2026-10-04.

    Prerequisites¶

    • The Manager role in a project with a queue that allows 2 GPUs
    • The ddp-trainer image from Build your own image from your laptop, or any image with PyTorch
    • About 15 minutes

    What you'll build¶

    Part Where it runs What it does
    Config file Project Config tab Describes the job: image, command, CPU, memory, GPUs, storage
    torchrun The job's container Starts one training process per GPU
    train_ddp.py Each process Trains its share of every batch; DDP averages the gradients
    /workspace Your storage CIFAR-10, TensorBoard logs, checkpoints

    Step 1: Write the training script¶

    The image from the previous post already has this file at /app/train_ddp.py:

    """Train ResNet-18 on CIFAR-10 with DistributedDataParallel.

Launch with torchrun; every process drives one GPU. Rank 0 writes
TensorBoard logs and checkpoints under --out.
"""
import argparse
import os
import time

import torch
import torch.distributed as dist
import torchvision
import torchvision.transforms as T
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data import DataLoader, DistributedSampler
from torch.utils.tensorboard import SummaryWriter


def loaders(data_dir, batch_size, rank):
    norm = T.Normalize((0.4914, 0.4822, 0.4465), (0.2470, 0.2435, 0.2616))
    train_tf = T.Compose([T.RandomCrop(32, padding=4), T.RandomHorizontalFlip(), T.ToTensor(), norm])
    if rank == 0:  # one download, the other ranks wait at the barrier
        torchvision.datasets.CIFAR10(data_dir, train=True, download=True)
        torchvision.datasets.CIFAR10(data_dir, train=False, download=True)
    dist.barrier()
    train = torchvision.datasets.CIFAR10(data_dir, train=True, transform=train_tf)
    test = torchvision.datasets.CIFAR10(data_dir, train=False, transform=T.Compose([T.ToTensor(), norm]))
    sampler = DistributedSampler(train)
    train_dl = DataLoader(train, batch_size, sampler=sampler, num_workers=6, pin_memory=True, persistent_workers=True)
    test_dl = DataLoader(test, 1000, num_workers=2)
    return train_dl, test_dl, sampler


def accuracy(model, test_dl, device):
    model.eval()
    correct = 0
    with torch.no_grad(), torch.autocast("cuda", dtype=torch.bfloat16):
        for x, y in test_dl:
            correct += (model(x.to(device)).argmax(1) == y.to(device)).sum().item()
    model.train()
    return correct / len(test_dl.dataset)


def main():
    p = argparse.ArgumentParser()
    p.add_argument("--data", required=True)
    p.add_argument("--out", required=True)
    p.add_argument("--epochs", type=int, default=10)
    p.add_argument("--batch-size", type=int, default=256, help="per GPU")
    args = p.parse_args()

    dist.init_process_group("nccl")
    rank, world = dist.get_rank(), dist.get_world_size()
    device = torch.device("cuda", int(os.environ["LOCAL_RANK"]))
    torch.cuda.set_device(device)

    train_dl, test_dl, sampler = loaders(args.data, args.batch_size, rank)
    model = torchvision.models.resnet18(num_classes=10).to(device, memory_format=torch.channels_last)
    model = DDP(model, device_ids=[device.index])
    lr = 0.1 * args.batch_size * world / 256  # linear scaling rule
    opt = torch.optim.SGD(model.parameters(), lr=lr, momentum=0.9, weight_decay=5e-4, nesterov=True)
    sched = torch.optim.lr_scheduler.OneCycleLR(opt, lr, epochs=args.epochs, steps_per_epoch=len(train_dl))
    loss_fn = torch.nn.CrossEntropyLoss()
    writer = SummaryWriter(os.path.join(args.out, f"gpus{world}")) if rank == 0 else None

    for epoch in range(args.epochs):
        sampler.set_epoch(epoch)
        torch.cuda.synchronize()
        start = time.time()
        for x, y in train_dl:
            x = x.to(device, non_blocking=True, memory_format=torch.channels_last)
            y = y.to(device, non_blocking=True)
            with torch.autocast("cuda", dtype=torch.bfloat16):
                loss = loss_fn(model(x), y)
            opt.zero_grad(set_to_none=True)
            loss.backward()
            opt.step()
            sched.step()
        torch.cuda.synchronize()
        seconds = time.time() - start
        if rank == 0:
            acc = accuracy(model.module, test_dl, device)
            imgs = len(train_dl.dataset) / seconds
            writer.add_scalar("train/loss", loss.item(), epoch)
            writer.add_scalar("test/accuracy", acc, epoch)
            writer.add_scalar("throughput/images_per_sec", imgs, epoch)
            print(f"epoch {epoch + 1}/{args.epochs}  loss {loss.item():.3f}  "
                  f"test acc {acc:.3f}  {seconds:.1f}s  {imgs:.0f} img/s", flush=True)
    if rank == 0:
        torch.save(model.module.state_dict(), os.path.join(args.out, f"resnet18-gpus{world}.pt"))
        writer.close()
    dist.destroy_process_group()


if __name__ == "__main__":
    main()

    ① DistributedSampler hands each process a different slice of the data, so two GPUs see each image once per epoch between them. ② The learning rate grows with the number of GPUs (0.1 × batch × GPUs / 256), because the effective batch grows too. ③ Only rank 0 downloads the data, writes logs and saves the model; the others wait at dist.barrier().

    Step 2: Write the config file¶

    Open Projects → [your project] → Config, click New File, and paste this as ddp-gpus2.yaml:

    apiVersion: batch/v1
kind: Job
metadata:
  name: ddp-resnet18-gpus2
spec:
  backoffLimit: 0
  template:
    metadata:
      labels:
        platform-go/dra-gpu-model: rtx5090
    spec:
      restartPolicy: Never
      containers:
        - name: train
          image: 192.168.110.1:30003/p26000001/ddp-trainer:v1
          command: ["torchrun", "--nproc_per_node=2", "/app/train_ddp.py",
                    "--data", "/workspace/cifar10", "--out", "/workspace/ddp-runs",
                    "--epochs", "15"]
          resources:
            requests:
              cpu: "16"
              memory: 48Gi
              nvidia.com/gpu-dra: "2"
            limits:
              cpu: "16"
              memory: 48Gi
              nvidia.com/gpu-dra: "2"
          volumeMounts:
            - name: storage
              mountPath: /workspace
      volumes:
        - name: storage
          persistentVolumeClaim:
            claimName: "{{userVolume}}"

    ① The platform-go/dra-gpu-model label and the nvidia.com/gpu-dra count are what the Resource Wizard writes when you pick a GPU model and count. The deploy dialog reads the model from the label. ② CPU and memory grow with the GPUs. Each training process runs six data-loading workers, and with eight CPUs for two GPUs the GPUs wait for data. ③ {{userVolume}} mounts your personal storage at /workspace, so the data and results outlive the job.

    For the one-GPU run, save a copy as ddp-gpus1.yaml with the name ddp-resnet18-gpus1, --nproc_per_node=1, nvidia.com/gpu-dra: "1", 8 CPUs and 24Gi.

    Step 3: Deploy¶

    Click Deploy on the file's version row, pick the queue, and confirm. The job appears under Resources → Pods; open its logs to follow the training:

epoch 2/15  loss 1.469  test acc 0.506  1.5s  32684 img/s
epoch 3/15  loss 1.008  test acc 0.559  1.5s  33115 img/s

epoch 13/15  loss 0.448  test acc 0.803  2.0s  25552 img/s

epoch 15/15  loss 0.433  test acc 0.821  1.6s  30897 img/s

    Before its first start, an image is scanned for known vulnerabilities; the pod waits in that step for a few minutes the first time and starts at once after that. The first run also downloads CIFAR-10 (170 MB) into /workspace/cifar10.

    Step 4: Compare one and two GPUs¶

    Deploy ddp-gpus1.yaml the same way. Both runs train for 15 epochs:

    GPUs Training time Images per second Test accuracy
    1 35.7 s 21,230 82.7%
    2 24.9 s 30,530 82.1%
    • Two GPUs are 1.4 times as fast, and reach the same accuracy within run-to-run noise.
    • The speed-up is below 2 because ResNet-18 on 32×32 images finishes a step in milliseconds. Every step still loads and augments images on the CPU and averages gradients between the GPUs, and those costs don't shrink with a second GPU. A larger model or larger images spend more of each step on the GPU and scale closer to 2.

    Each run leaves a folder under /workspace/ddp-runs/ (gpus1/, gpus2/) with TensorBoard logs, and a checkpoint such as resnet18-gpus2.pt. Look at training results in a GPU desktop plots them.

    What you built¶

    A training job you describe once in YAML and deploy on as many GPUs as the queue allows, with every run's logs and checkpoints in your storage. To use it for your own model:

    • Swap the dataset and model in train_ddp.py; keep DistributedSampler, DDP(...) and the rank-0 checks.
    • Change only the GPU count, --nproc_per_node and the CPUs and memory to scale up.
    • Deleting a finished job's instance frees its entry; the files in /workspace stay.
