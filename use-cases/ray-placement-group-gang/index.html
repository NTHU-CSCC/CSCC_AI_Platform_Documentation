    Start a Ray job only when all its GPUs are there¶

    A job that needs two GPUs at once hangs or fails if it starts with only one. With X-CSCC-Gang: true, the platform starts all of the session's GPU workers together or none of them, and a Ray placement group makes your code wait until Ray sees every GPU. In the run below, both RTX 5090 workers were placed in the same second, the script had both GPUs 2.7 seconds after it started, and the whole job took 29 seconds from submit on a session that did not exist yet.

    Prerequisites¶

    • Your laptop set up as in Submit a job: Ray 2.58.0, the root certificate, an API token
    • A queue that allows 2 GPUs in your project

    Step 1: Write the script¶

    Save this as gang.py in an empty folder:

    import os
import socket
import time

import ray
from ray.util.placement_group import placement_group, remove_placement_group
from ray.util.scheduling_strategies import PlacementGroupSchedulingStrategy

N = int(os.environ.get("N_GPUS", "2"))
WAIT = int(os.environ.get("WAIT_SECONDS", "600"))

@ray.remote(num_gpus=1)
class Rank:
    def where(self):
        return socket.gethostname(), ray.get_gpu_ids()

ray.init()
start = time.time()
pg = placement_group([{"CPU": 1, "GPU": 1}] * N, strategy="PACK")
try:
    ray.get(pg.ready(), timeout=WAIT)
except ray.exceptions.GetTimeoutError:
    remove_placement_group(pg)
    raise SystemExit(f"not all {N} GPUs were free within {WAIT}s; released them")
print(f"all {N} GPUs ready after {time.time() - start:.1f}s")

strategy = PlacementGroupSchedulingStrategy(placement_group=pg)
ranks = [Rank.options(scheduling_strategy=strategy).remote() for _ in range(N)]
for i, (host, gpus) in enumerate(ray.get([r.where.remote() for r in ranks])):
    print(f"rank {i}: {host} GPU {gpus}")
remove_placement_group(pg)
    • Each bundle is {"CPU": 1, "GPU": 1} because a Ray actor also takes one CPU. With {"GPU": 1} alone, the actors do not fit and Ray stops with cannot fit into any bundles.
    • pg.ready() returns only when every bundle is placed. The workers start together, but each needs a few seconds to join Ray, so the script still waits for them. Replace the Rank part with your own training.

    Step 2: Ask for the GPUs¶

    Put the session settings in RAY_JOB_HEADERS. X-CSCC-Gang: true starts all X-CSCC-GPUs workers together. Set X-CSCC-GPUs to N_GPUS: a session with fewer GPUs than the script asks for makes it wait until WAIT_SECONDS runs out.

    export RAY_JOB_HEADERS='{"Authorization":"Bearer cscc_xxx","X-CSCC-GPUs":"2","X-CSCC-Queue":"<queue>","X-CSCC-Gang":"true"}'

    For the value of <queue>, see Find your queue name.

    Step 3: Submit¶

    Pass N_GPUS and WAIT_SECONDS in the job's runtime_env, in whichever form suits you:

    ray job submit --working-dir . \
  --runtime-env-json '{"env_vars":{"N_GPUS":"2","WAIT_SECONDS":"600"}}' \
  -- python gang.py

    runtime_env.yaml:

    env_vars:
  N_GPUS: "2"
  WAIT_SECONDS: "600"

    ray job submit --working-dir . --runtime-env runtime_env.yaml -- python gang.py

    This uploads no folder, so put gang.py in your storage first, for example /home/<your username>/ray-demo/. job.json:

    {
  "entrypoint": "python /home/<your username>/ray-demo/gang.py",
  "runtime_env": {"env_vars": {"N_GPUS": "2", "WAIT_SECONDS": "600"}}
}

    curl -X POST "$RAY_ADDRESS/api/jobs/" \
  -H "Authorization: Bearer cscc_xxx" -H "X-CSCC-GPUs: 2" -H "X-CSCC-Queue: <queue>" -H "X-CSCC-Gang: true" \
  -H "Content-Type: application/json" -d @job.json

    Read the output with ray job logs <job id>, or GET $RAY_ADDRESS/api/jobs/<job id>/logs.

    Results¶

    First submit, with no session running:

    all 2 GPUs ready after 2.7s
rank 0: ray-session-gpu-workers-worker-sw6vh GPU [0]
rank 1: ray-session-gpu-workers-worker-7rnn2 GPU [0]

    Both workers were placed in the same second. Two more submits to the same session each took 0.2 seconds, because the workers were still up.

    When only one RTX 5090 was free, neither worker started. Both waited, and no GPU hours counted until both GPUs were free.

    Scale to 8 GPUs¶

    Change the GPU count in the headers and in N_GPUS; the script stays the same:

    export RAY_JOB_HEADERS='{"Authorization":"Bearer cscc_xxx","X-CSCC-GPUs":"8","X-CSCC-Queue":"rtx5090-queue","X-CSCC-Gang":"true"}'
ray job submit --working-dir . \
  --runtime-env-json '{"env_vars":{"N_GPUS":"8","WAIT_SECONDS":"3600"}}' \
  -- python gang.py
    • Your plan and your per-user GPU limit must both allow 8 GPUs. If they allow fewer, the submit is refused with the number that fits.
    • Each machine has 4 RTX 5090s, so 8 GPUs span two machines. For NCCL between machines, see Run one NCCL job on GPUs in several machines with your own Ray image.
    • Pick a queue that is not preemptible. If the session is preempted, all its workers stop together and the session ends; the next submit starts a new one.

    Limits¶

    • The workers stay until the session ends and count GPU hours the whole time, even between jobs. Select End session on the Ray tab when you are done.
    • If not every GPU is free, the session waits with none of them. If it keeps waiting, ask for fewer GPUs or try later.
