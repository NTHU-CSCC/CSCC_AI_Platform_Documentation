    Sweep hyperparameters across GPUs with Ray¶

    Trying eight hyperparameter combinations one after another in a workspace takes eight times as long as one. With a Ray job, you send the whole sweep from your laptop and the platform runs one combination per GPU at the same time. In the run below, all eight trials finished in 17 seconds on two RTX 5090s.

    In this post you run a learning-rate and L2 sweep on two GPUs. By the end you have:

    • A Ray Tune script that gives each trial its own GPU
    • The sweep running on the platform, sent from your laptop
    • Every trial's results in your storage, and the best setting printed

    The commands and output below come from a run on the platform on 2026-10-03.

    Prerequisites¶

    • VPN access, a project you belong to, and an API token (Settings)
    • Python 3.10 or later on your laptop
    • A queue that allows 2 GPUs in your project
    • About 10 minutes

    What you'll build¶

    Part Where it runs What it does
    ray command Your laptop Uploads the folder, sends the job, shows the output
    Ray session The platform Starts on the first submit, ends after 30 idle minutes or at its maximum lifetime
    GPU workers The platform One per running trial, up to X-CSCC-GPUs
    ray-results/ Your storage Each trial's settings and per-epoch metrics

    Step 1: Set up your laptop¶

    Install Ray, trust the platform's Root certificate (from Settings → Security → Downloads), and say what you need. Submit a job explains each line.

    pip install "ray[default]==2.58.0"
export REQUESTS_CA_BUNDLE=~/Downloads/cscc-root-ca.pem
export SSL_CERT_FILE=~/Downloads/cscc-root-ca.pem
export RAY_JOB_HEADERS='{"Authorization":"Bearer cscc_xxx","X-CSCC-GPUs":"2","X-CSCC-Queue":"<queue>"}'
export RAY_ADDRESS=https://api.cscc.nthu.edu.tw/api/v1/projects/<project id>/ray

    With RAY_ADDRESS set, ray job commands need no --address. If your plan and queue allow more than one GPU model, also add "X-CSCC-GPU-Model":"<model>" to the headers.

    Step 2: Write the sweep¶

    The platform's Ray image has NumPy, CuPy, pandas, Ray Tune and Ray Data, but no PyTorch, so the model is a logistic regression in CuPy. Save this as sweep.py in an empty folder:

    """Sweep learning rate and L2 strength for a logistic-regression model on GPU.

Each trial trains on one GPU with CuPy; Ray Tune runs one trial per GPU worker.
"""
import argparse

import cupy as cp
from ray import tune


def make_data(n=200_000, d=512, seed=0):
    rng = cp.random.default_rng(seed)
    w_true = rng.standard_normal(d, dtype=cp.float32)
    x = rng.standard_normal((n, d), dtype=cp.float32)
    y = (x @ w_true + 0.5 * rng.standard_normal(n, dtype=cp.float32) > 0).astype(cp.float32)
    split = int(n * 0.8)
    return x[:split], y[:split], x[split:], y[split:]


def train(config):
    x, y, xv, yv = make_data()
    w = cp.zeros(x.shape[1], dtype=cp.float32)
    for epoch in range(config["epochs"]):
        p = 1 / (1 + cp.exp(-(x @ w)))
        grad = x.T @ (p - y) / len(y) + config["l2"] * w
        w -= config["lr"] * grad
        acc = float(((xv @ w > 0) == (yv > 0.5)).mean())
        tune.report({"val_acc": acc, "epoch": epoch + 1,
                     "gpu": cp.cuda.runtime.getDeviceProperties(0)["name"].decode()})


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--out", required=True, help="results folder in your storage")
    args = parser.parse_args()

    tuner = tune.Tuner(
        tune.with_resources(train, {"gpu": 1}),
        param_space={
            "lr": tune.grid_search([0.01, 0.1, 1.0, 5.0]),
            "l2": tune.grid_search([0.0, 0.01]),
            "epochs": 50,
        },
        tune_config=tune.TuneConfig(metric="val_acc", mode="max"),
        run_config=tune.RunConfig(name="lr-l2-sweep", storage_path=args.out),
    )
    results = tuner.fit()
    df = results.get_dataframe()[["config/lr", "config/l2", "val_acc", "gpu"]]
    print(df.sort_values("val_acc", ascending=False).to_string(index=False))
    print("best:", results.get_best_result().config)

    ① tune.with_resources(train, {"gpu": 1}): one GPU per trial, so Ray starts one worker per running trial. ② storage_path=args.out: results go to your storage, because the cluster's own disk is gone when it ends.

    Step 3: Submit the job¶

    ray job submit \
  --working-dir . \
  -- python sweep.py --out /home/<your username>/ray-results

    In this run the session was ready 17 s after the first submit; it can take up to a minute. The command then follows the output until the job ends.

    Step 5: End the session¶

    The session closes after 30 minutes with no job. To release the GPUs now, open the project's Ray tab and select End session under Ray sessions. The files in your storage stay.

    What you built¶

    A sweep you edit on your laptop and run on the platform's GPUs, two trials at a time, with results kept in your storage. To use it for your own work:

    • Replace make_data and the loop in train with your model; keep tune.report.
    • Run more trials at once: raise X-CSCC-GPUs (at most 10), then end the session so the next submit starts a new cluster.
    • Read data from your storage and leave it out of the upload with .gitignore (limit 500 MiB).
    • If you need PyTorch, ask for it under Requests (details).
