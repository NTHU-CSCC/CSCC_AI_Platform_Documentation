    Serve a 14B LLM across two GPUs with vLLM¶

    Qwen2.5-14B-Instruct is a capable open model, and in 16-bit precision its weights alone take about 28 GB. That is nearly all of a 32 GB RTX 5090, leaving no room for the KV cache, the memory each conversation needs. Tensor parallelism splits every layer across two GPUs, so each card holds half the weights and the rest goes to the cache. In the run below, vLLM on two RTX 5090s served the model at 2,625 tokens per second across 64 parallel requests. On one card it would not start at all.

    In this post you serve the model from a workspace and call it with the OpenAI Python client. By the end you have:

    • The model's weights in group storage, downloaded once and reused by every server you start
    • A vLLM server on two GPUs with an OpenAI-compatible API
    • Measured throughput for one request and for 64 at once, and proof that one GPU is not enough

    The commands and output below come from a run on the platform on 2026-10-04.

    Prerequisites¶

    • A project with a queue that allows 2 GPUs, and a group storage volume with about 35 GB free bound to it (Storage)
    • A workspace in that project with the group volume ticked; it needs no GPU of its own
    • About 30 minutes, most of it the one-time download

    What you'll build¶

    Part Where it runs What it does
    Workspace The platform Your terminal: downloads the model, starts and calls the server
    vLLM server Its own job with 2 GPUs Loads half of every layer on each GPU and answers OpenAI API calls
    models/ Group storage The 29.5 GB of weights, shared by every server and lab member

    Step 1: Download the model into group storage¶

    Check free space with df -h /home/<your username> /mnt/shared/<volume name>. In this run personal storage had 10 GiB, too small for the model, so it goes to group storage, where your lab can reuse it too. In the workspace terminal:

    pip install --user "huggingface_hub[hf_xet]==1.32.0"
export PATH=$HOME/.local/bin:$PATH
hf download Qwen/Qwen2.5-14B-Instruct --local-dir /mnt/shared/<volume name>/models/Qwen2.5-14B-Instruct

    The download is 29.5 GB in eight files. It resumes where it stopped if the workspace restarts, so run the same command again.

    Step 2: Start the server on two GPUs¶

    Workspaces have a docker command that starts containers next to the workspace (Using docker in the IDE):

    docker run -d --keep --name qwen14b --gpus 2 --cpus 8 -m 48g --shm-size 8g \
  -p 8000:8000 \
  -v /mnt/shared/<volume name>/models:/models:ro \
  -e HOME=/tmp \
  vllm/vllm-openai:v0.30.0 \
  --model /models/Qwen2.5-14B-Instruct --served-model-name qwen2.5-14b \
  --tensor-parallel-size 2 --max-model-len 8192

    ① --keep --gpus 2 gives the container two GPUs of its own, from your project's quota. The workspace has no GPU to share, so the container gets its own. ② -p 8000:8000 publishes the API on 127.0.0.1:8000 inside the workspace. ③ -v …:/models:ro mounts the weights read-only, so a server can never damage the shared copy. ④ -e HOME=/tmp keeps vLLM's compile cache inside the container instead of in a home folder. ⑤ --tensor-parallel-size 2 splits each layer across the two GPUs.

    Follow the start-up with docker logs -f qwen14b. The lines that matter:

    Model loading took 13.93 GiB memory and 47.540906 seconds
GPU KV cache size: 149,488 tokens, Maximum concurrency for 8,192 tokens per request: 18.25x
init engine (profile, create kv cache, warmup model) took 176.75 s (compilation: 20.35 s)
Application startup complete.

    Each GPU holds 13.93 GiB, half the weights, and the rest of its memory holds a 149,488-token cache: room for 18 full-length conversations at once. In this run the server was ready 8 minutes after docker run. Of that, 2 minutes 42 seconds was the image's security check and first pull, which later starts skip.

    Step 3: Call the model¶

    The server speaks the OpenAI API, so the official client works with only the base URL changed. Save this as bench.py in the workspace:

    """Ask the vLLM server one question, then measure throughput under load.

Usage: python bench.py [concurrent requests]
"""
import asyncio
import sys
import time

from openai import AsyncOpenAI

client = AsyncOpenAI(base_url="http://127.0.0.1:8000/v1", api_key="unused")
MODEL = "qwen2.5-14b"


async def ask(prompt, max_tokens=256):
    r = await client.chat.completions.create(
        model=MODEL, messages=[{"role": "user", "content": prompt}],
        max_tokens=max_tokens, temperature=0.7)
    return r.choices[0].message.content, r.usage.completion_tokens


async def main(n):
    start = time.time()
    answer, tokens = await ask("用三句話解釋什麼是 tensor parallelism。")
    print(f"{answer}\n-- {tokens} tokens in {time.time() - start:.2f}s\n")

    prompts = [f"Write a short story about GPU number {i}." for i in range(n)]
    start = time.time()
    results = await asyncio.gather(*(ask(p) for p in prompts))
    seconds = time.time() - start
    total = sum(t for _, t in results)
    print(f"{n} concurrent requests: {total} tokens in {seconds:.1f}s = {total / seconds:,.0f} tokens/s")


asyncio.run(main(int(sys.argv[1]) if len(sys.argv) > 1 else 64))

    pip install --user openai==2.8.1
python bench.py 1
python bench.py 64

    Tensor parallelism是一種在深度學習模型訓練中分發計算和數據的方法，它將大型張量（多維數組）分割成更小的部分，並在不同的處理器或設備上並行處理這些部分。這種技術可以加速模型的訓練過程並允許使用更大的模型和數據集。
-- 68 tokens in 1.01s

1 concurrent requests: 256 tokens in 2.9s = 88 tokens/s
…
64 concurrent requests: 16384 tokens in 6.2s = 2,625 tokens/s

    Results¶

    Setup Result
    2 GPUs, 1 request 88 tokens/s
    2 GPUs, 64 requests at once 2,625 tokens/s
    1 GPU Does not start: No available memory for the cache blocks
    • One request at a time uses a fraction of the GPUs. vLLM batches concurrent requests together, so 64 at once produced 30 times the tokens per second.
    • On one GPU, the same command with --gpus 1 and no --tensor-parallel-size loaded 27.57 GiB of weights, then stopped: there was no memory left for the KV cache. Two GPUs are what make this model servable on these cards at all.

    Step 4: Stop the server¶

    A --keep container keeps its GPUs even after the workspace stops, and counts toward your project's job limits and GPU hours. Remove it when you're done:

    docker rm -f qwen14b

    The weights stay in group storage for next time; the next start skips the download.

    What you built¶

    An OpenAI-compatible endpoint for a 14B model, split across two GPUs, with the weights stored once for your whole lab. Next:

    • Point any OpenAI client, LangChain or LlamaIndex at http://127.0.0.1:8000/v1 from the workspace.
    • Try a larger model with --gpus 4 --tensor-parallel-size 4 if your plan allows four GPUs.
    • Serve a quantized build (for example an AWQ variant) when one GPU is all you can get.
    • Keep the vLLM version pinned; a new tag waits for its security check the first time it starts.
