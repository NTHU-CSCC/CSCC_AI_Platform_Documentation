    Ray 工作¶

    在筆電上用 ray 指令提交工作，跑在平台的 GPU 上。叢集由平台啟動和移除，改程式不用重建映像。

    可用性

    管理員開啟後才能用 Ray 工作。如果下面的指令在每個專案都被拒絕，請聯絡管理員。

    提交工作¶

    你需要 VPN 連線、一個你所屬的專案，以及一個 API token。

    1. 在 設定 → 安全性 建立 API token，或用 cscc-cli（見命令列工具與設定）。token 只會顯示一次，記得先複製。

    2. 在筆電上安裝 Ray，版本要和平台一致，是 2.58.0：

      pip install "ray[default]==2.58.0"

    3. 到設定 → 安全性 → 下載下載 根憑證，再讓 Ray 用它。少了這一步，ray 會報 certificate verify failed：

      export REQUESTS_CA_BUNDLE=~/Downloads/cscc-root-ca.pem
export SSL_CERT_FILE=~/Downloads/cscc-root-ca.pem

      ray 提交時用第一個，看輸出時用第二個，兩個都要設。

    4. 把 token 和需求寫進環境變數：

      export RAY_JOB_HEADERS='{"Authorization":"Bearer cscc_xxx","X-CSCC-GPUs":"2","X-CSCC-Queue":"default-batch"}'

    5. 在程式碼資料夾裡提交。<project id> 換成專案網址 /projects/<project id> 裡的數字：

      ray job submit \
  --address https://api.cscc.nthu.edu.tw/api/v1/projects/<project id>/ray \
  --working-dir . \
  -- python train.py

    指令會上傳資料夾、顯示輸出、印出工作 ID。之後用同一個 --address 執行 ray job status <job id>、ray job logs <job id>、ray job stop <job id>。

    選擇 GPU¶

    標頭放在 RAY_JOB_HEADERS，只在建立叢集時讀取。叢集已在跑就會忽略，要改請等叢集結束再提交。

    每個 worker 一張 GPU，所以 X-CSCC-GPUs 也是 worker 上限。worker 有工作才啟動，閒置約一分鐘就停止。

    標頭 意義 省略時
    X-CSCC-GPUs 叢集最多用幾張 GPU，也就是最多幾個 worker 1
    X-CSCC-Queue worker 跑在哪個排程佇列。不能選 burst 佇列 平台預設值
    X-CSCC-GPU-Model 要用哪種 GPU 型號 你的方案和佇列只允許一種時，用那一種。允許多種就會提交失敗，要自己指定
    X-CSCC-Image head 與 worker 用的映像：專案可用於工作的任何映像，但不能是其他專案 Harbor 專案裡的映像，且須通過映像掃描。必須含 ray[default]==2.58.0，並以 UID 1000 執行 平台的 Ray 映像

    什麼會計入配額¶

    • 叢集開著的期間，你要的 GPU 會從專案的 GPU 配額和你個人的 GPU 上限扣掉，別人不能用。
    • GPU 時數 只算執行中的 worker。叢集結束後 GPU 就釋放。
    • 同一個專案裡，你同時最多持有 10 個 GPU claim，所以一個叢集最多 10 個 GPU worker。

    可用的 GPU 比你要的少時，叢集的上限會降到放得下的數量。連一張都放不下，提交才會失敗，不會建立任何東西；請換佇列或稍後再試。

    第一次提交與叢集結束¶

    第一次提交要啟動新叢集，約 30–60 秒，指令最多等 2 分鐘。還沒就緒會回 503，再執行一次即可。之後的工作會馬上開始。

    出現以下任一情況，平台就會移除叢集：

    • 連續 30 分鐘沒有執行中的 Ray 工作。
    • 到了存活時間上限。上限取三者中最短的：專案的最長工作執行時間、佇列的執行時間上限、24 小時。到時還在跑的工作會被停掉。

    下次提交會開新叢集，寫在叢集磁碟上的東西會消失，結果請存到儲存空間（見下）。

    查看與結束工作階段¶

    打開專案的 Ray 分頁（平台開了 Ray 工作階段才會出現）。Ray 工作階段列出你目前的工作階段：狀態、佔用的 GPU、佇列、開始時間，以及最晚結束（最晚會跑到什麼時候）。閒置超過最晚結束下方顯示的時間，會提早結束。

    選 結束工作階段 可立刻停止：Ray 工作停止，GPU 馬上釋放。下次 ray job submit 會開新的工作階段。

    沒有工作階段時，這一區會顯示這個專案的 --address，旁邊有複製按鈕。

    把資料放在儲存空間¶

    每個叢集都會掛載你的檔案，跟工作區一樣：

    儲存空間 路徑
    個人 /home/<你的使用者名稱>
    群組 /mnt/shared/<儲存空間名稱>

    資料集從這些路徑讀，檢查點和結果寫回這裡。權限照你在儲存空間上的設定（見儲存）。

    上傳的內容與映像的內容¶

    • 上傳的是工作資料夾，壓成 zip，上限 500 MiB。.gitignore 列到的檔案不會上傳，所以資料集、模型權重和虛擬環境請寫進 .gitignore，或放在儲存空間。
    • 沒有指定 X-CSCC-Image 時，worker 用平台的 Ray 映像，內建 NumPy、CuPy、pandas、Ray Tune 和 Ray Data，沒有 PyTorch。需要其他大型套件，請自己建映像，再用 X-CSCC-Image 指定。
    • runtime_env 的下載（pip、conda、git）需要專案開啟對外網路。沒開的話，就把套件裝進映像，或從自己的儲存空間安裝。

    完整範例見使用案例：用 Ray 在多張 GPU 上搜尋參數。

    worker 之間的 RDMA¶

    RDMA 由管理員逐專案開啟。開啟後，專案裡每個 worker 都會接上 25 Gbit/s 的 RoCE 網路，NCCL 不用設定就會使用。要和 TCP 比較，在工作的 runtime_env env_vars 設 NCCL_IB_DISABLE=1。

    你的映像需要 ibverbs-providers 套件，沒有的話 NCCL 會悄悄退回 TCP。用 NCCL_DEBUG=INFO 看 NCCL 日誌有沒有 NET/IB。

    錯誤¶

    訊息 原因與處理
    400 X-CSCC-Queue 指到不存在的佇列，或 X-CSCC-Image 不是有效的映像名稱。檢查設定值。
    401 token 沒帶、過期或已撤銷。重新建一個，更新 RAY_JOB_HEADERS。
    403 你不是這個專案的成員。檢查專案編號，或問專案管理者。
    409 或 422 要求違反配額或規則：連一張 GPU 都放不下、X-CSCC-Image 來自其他專案或未通過映像掃描、用了方案不允許的佇列或 GPU 型號、選了 burst 佇列，或超過 10 個 GPU claim。方案和佇列允許多種 GPU 型號時，要加 X-CSCC-GPU-Model。訊息會說明是哪一項。
    422 加原因 叢集啟動失敗，或平台拒絕了叢集設定。原因寫在訊息裡，不會留下執行中的叢集。
    503 加 Retry-After 叢集還在啟動。再執行一次指令。如果超過幾分鐘還是這樣，請聯絡管理員。
    Failed to connect to Ray at address 叢集 2 分鐘內沒準備好，常見於新映像還在下載。再執行一次同一個指令。
    WebSocket connection closed unexpectedly with close code 1006 工作已經收下，只是輸出串流斷了，常見於 worker 啟動時。工作會繼續跑，用 ray job logs <job id> 追蹤。
    上傳失敗 套用 .gitignore 後資料夾還是超過 500 MiB，或上傳太久。把大檔案移掉。
