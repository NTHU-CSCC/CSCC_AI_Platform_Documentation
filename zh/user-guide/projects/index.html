    專案¶

    專案是平台上資源分配的主要單位。你啟動的每個工作區都會消耗專案的配額，每個設定檔或部署都屬於某個專案。

    適用對象： 所有已登入的使用者。帳號建立時會自動產生一個個人專案。

    專案頁面布局¶

    圖 1：專案列表，預設為列表模式。

    專案頁面支援兩種檢視模式：

    • 列表模式（預設） — 精簡的可排序表格
    • 卡片模式 — 顯示專案名稱、描述、成員數、GPU 使用量長條

    使用工具列右上角的圖示切換檢視模式。

    建立專案¶

    建立專案需要 manage-projects 權限。若你沒有這項權限，新建專案 按鈕不會顯示， 直接開啟建立頁面也會被導回專案列表。請改請管理員幫你建立。帳號建立時， 系統已經自動幫你開好一個個人專案。

    1. 點左側選單的 專案。
    2. 點 新建專案（右上角按鈕；僅在具備 manage-projects 權限時顯示）。
    3. 填寫專案表單：
    欄位 說明
    名稱 簡短的英數識別碼（可使用連字號）
    群組 專案所屬的群組（必填）
    描述 選填，專案用途說明
    1. 點 建立。專案會立即出現在你的列表中。

    配額由管理員指派

    新建的專案 GPU 配額從零開始。請聯繫管理員或透過 申請 提交資源申請，將資源計畫繫結到你的專案。

    專案詳情標籤¶

    點專案開啟詳情頁面。核心標籤包含總覽、設定、計畫、建置、GPU Claims 與資源；映像、成員、儲存、設定等標籤會依你的專案角色顯示。

    圖 2：專案詳情頁面，包含總覽、設定、計畫、建置、GPU Claims、資源與依角色顯示的標籤。

    標籤 內容
    總覽 描述、配額使用圖表、GPU 時數額度、當前計畫、成員列表摘要
    設定 版本化的設定檔，描述你要執行的內容
    計畫 綁定的資源計畫、計畫時段、允許的 GPU 型號與配額範圍
    建置 專案容器映像建置、來源選擇、共用佇列狀態與即時建置日誌
    GPU Claims 可預先建立、之後再掛到部署上的 GPU 保留
    資源 依成員彙整的即時 GPU/CPU/Memory 使用量，可展開查看各成員執行中的資源
    映像 / 成員 / 儲存 依角色顯示的映像管理、成員管理、個別配額或儲存權限標籤
    設定 套用到整個專案的工作區限制，見下方「專案設定」

    角色門檻：儲存、映像 與 設定 標籤需要 Project Manager 以上；成員 標籤僅 Project Admin 可見（平台管理員需在右上角頭像切換至 Admin View 才會被視為有效的 Project Admin）。平台會阻止 Admin 將自己降級，避免專案失去最後一位 Admin。

    專案設定¶

    設定 標籤（Project Manager 以上）放的是套用到專案內所有工作區的限制：

    欄位 作用
    Workspace 最長連續使用時間 單位是秒。執行超過這個時間的工作區會被自動停止。0 代表不限制（預設）。

    點 儲存變更 套用。這個上限也會限制從此專案啟動的 GPU 桌面 的存活時間。

    建置專案映像¶

    當專案需要允許清單中沒有的容器映像時，請使用 建置 標籤。專案管理者與專案管理員可在專案啟用 image build 後觸發建置；一般專案成員可以查看狀態與日誌，但不能啟動或刪除建置。

    來源模式¶

    來源 使用時機
    上傳 archive 上傳 .tar.gz 或 .zip build context，Dockerfile 需放在根目錄
    只貼 Dockerfile 直接貼上 Dockerfile，平台會建立最小 build context

    建置設定¶

    欄位 說明
    映像名稱 短名稱，例如 trainer-api；完整映像路徑由平台產生
    Tag 選填；留空使用平台預設，也可填 v1.0.1 等版本
    建置來源 上傳 archive，或直接貼 Dockerfile

    映像建置會送進共用佇列，同一時間只跑一個。每個建置固定分配一份 CPU、記憶體與暫存空間， 表單中無法調整，也不會占用專案或個人的配額。

    上傳的壓縮檔會在建置開始前檢查不安全路徑與檔案大小。

    提交後，建置歷史會顯示狀態、來源類型、目的映像與即時日誌。失敗的建置在表格中只顯示簡短摘要， 完整錯誤請點該列的日誌按鈕查看；若建置被重試，日誌畫面會保留前一次的失敗原因。

    每筆建置有幾個圖示操作：執行中可 取消建置（已產出映像的則是 刪除映像 artifact）、清除保存日誌、刪除歷史紀錄。 建置者與專案管理者可以清除已完成或失敗建置保存的日誌，建置歷史與映像不受影響。 啟動該次建置的成員本人或專案管理者，也可以在沒有其他項目引用時，刪除該筆歷史紀錄。

    專案管理者只能為自己管理的專案提交映像申請或移除映像項目；專案成員可以查看該專案的映像申請歷史。

    映像 分頁分成 可使用 與 申請紀錄 兩個子分頁。可使用列出這個專案已經能拉取的 映像；申請紀錄列出這個專案的所有映像申請（待審核的排在最前面），顯示狀態、送出時間與審核 備註，分頁標籤上還有待審核件數的徽章。透過 新增 送出申請後會自動切到申請紀錄分頁， 讓你立刻看到剛送出的那一筆。

    自己送出的申請在尚未審核前可以按 撤回 收回，之後仍可重新提出。別人送出的申請， 或是已核准／已拒絕的申請，不會出現撤回按鈕。

    被核准為全域的申請會從清單消失

    管理員核准時若勾選 設為全域，該申請就不再屬於這個專案，會從申請紀錄分頁消失； 映像本身則會出現在 可使用 分頁。

    建置權限由專案治理控制

    如果建置表單未顯示，代表專案尚未啟用 Image Build Permission，或你的專案角色不能啟動建置。建置歷史與日誌仍會保留可見，方便檢查既有工作。請聯繫專案管理者或平台管理員調整專案設定或角色。

    GPU Claims¶

    GPU Claims 標籤列出你可以在部署之前預先建立的 GPU 保留。claim 一建立就會先占用 GPU 配額， 但要等到有執行中的工作負載實際掛上去之後才開始累計 GPU 時數。只要設定檔中宣告了 GPU claim slot， 就能在部署對話框中挑選要用哪個 claim。

    建立 Claim¶

    這個分頁與表單在介面上是英文。填好 Create GPU ResourceClaim 表單後點 Create：

    欄位 說明
    Claim name 掛到部署上時使用的名稱，僅限英數字與連字號。
    GPU device class 要保留的 GPU 型號。表單預設選一個具體型號，不在意型號時才選 Any。
    GPU count 此 claim 保留的實體 GPU 張數；多張 GPU 仍算同一筆保留。
    SM share 1% 至 100% 的計算切片；表單旁會顯示對應的有效 GPU 數量。
    VRAM mode Elastic 與其他工作負載共用顯示記憶體；Hard cap 則強制套用所選比例。
    VRAM share 僅在選擇 Hard cap 時有效，保留量依所選型號中最小一張卡推算。

    Deployment 的每個 replica 都共用同一個 claim。2 張 GPU 的 claim 不管跑幾個 replica，都仍是同一筆 2-GPU 保留，配額與 GPU 時數也以每個 claim 計算一次，而不是每個 replica 計算一次。

    尚未使用的 claim GPU 時數為 0，但仍會占用專案與個人的 GPU 配額。表格欄位是 Name、Owner、GPU、SM、VRAM、Status、Allocation，加上刪除圖示。 Status 有三種：Reserved（已建立，還沒掛任何東西）、Allocated（已配到 GPU）、In use by <部署名稱>。 未使用的 claim 可以刪除，正在被執行中的工作負載使用的則不行。

    Claim 擁有權

    專案成員可以建立自己的 claim。專案管理者另可查看與刪除其他成員建立的 claim。

    計畫時段倒數¶

    當專案的資源計畫定義了計畫時段時，計畫 標籤會顯示距離下一個邊界的即時倒數：

    • 時段開啟時顯示 Window closes in HH:MM:SS。
    • 下一個時段尚未開啟時顯示 Window opens in HH:MM:SS。
    • 若沒有排程限制則顯示 Always active。

    部署對話框也會顯示同樣的倒數（計畫時段將在 HH:MM:SS 後關閉），並提醒時段關閉時工作負載可能被驅逐。 時段過了之後，對話框會顯示 計畫時段已過期，附 切換至預設佇列 連結，把這次部署改到預設佇列；這個橫幅只給部署用，工作區不能換佇列。時段結束時，計畫綁定佇列中的工作負載會被停止； 若計畫被移除或不再允許你選的佇列，還在等待啟動的工作也會一併取消。沒有綁定有效計畫的專案無法啟動任何工作負載。

    佇列也可能設有執行時間上限。若你選的佇列有這項限制，工作負載會在指定秒數後自動停止。 這是管理員設定的政策，無法從自己的設定檔提高或關閉。

    計畫若設有 GPU 時數額度，總覽 標籤會多一條 GPU 時數 長條：本期已分配的 GPU 時數對上額度、重設週期（每月、每週或每 N 小時，由管理員設定），以及下次重設時間（UTC+8）。額度用完後，新的 GPU 任務與工作區會被擋下，直到重設；執行中的不受影響。

    設定檔版本控制¶

    每次儲存都會建立一個新版本，舊版本永遠不會被覆蓋，隨時可以回頭查看或重新部署。 編輯或上傳設定檔後儲存，就會產生新版本；任何版本都可以拿來部署。

    操作設定檔¶

    1. 前往 專案 → [你的專案] → 設定 標籤。
    2. 點 新增檔案 上傳 YAML 檔案或在編輯器中貼上內容。
    3. 每次儲存都會建立新版本。
    4. 點設定旁的 歷史 圖示查看所有版本。
    5. 要部署特定版本，點版本列的 部署 按鈕。
    6. 在彈出的部署對話框中選擇排程佇列。若 YAML 包含 GPU claim slot，請為每個 slot 選擇本次部署要使用的已保留 GPU claim。

    執行中的實例會出現在專案的 資源 分頁。另外有一個 部署 頁面在 /projects/<專案 ID>/deployments，分 個人 與 成員 兩個分頁列出部署；側欄沒有連結，要用網址開。

    可以進去操作的容器¶

    要能對容器開啟 終端，它必須持續執行。單獨執行 Shell 而不帶參數 （例如 command: ["/bin/sh"]）會立刻結束，容器因此不斷重啟，每次開啟終端都會失敗。

    請改成讓容器有事可做：

    command: ["sleep", "infinity"]

    或在資源精靈的 互動式 Shell 區塊勾選 stdin 與 tty（手寫 YAML 則是 stdin: true 與 tty: true）讓 Shell 保持存活。當精靈偵測到單獨的 Shell 會立 刻結束時，會直接跳出警告。

    容器啟動後，前往專案的 資源 分頁，在 Pod 那一列點 終端。 Deployment 與 Job 的列上沒有終端按鈕，請展開找到它們建立的執行實例。

    部署規則¶

    部署、驗證、查看與刪除設定檔實例都需要 專案管理者 以上的角色。 配額會把你手上所有還沒結束的工作一起計算，所以還在排隊等待啟動的工作負載，在結束或被移除之前仍會占用配額。 設定檔可以部署 Pod、Deployment 與 Job，其他類型不接受。

    每個容器都必須同時設定記憶體的 request 與 limit，且至少 128Mi；缺少任一項會在部署與 dry-run 驗證時被拒絕。 單位一定要寫出來：只寫 memory: "1" 代表 1 byte，會被拒絕。

    要 GPU 的兩種方式¶

    設定檔有兩種方式可以要 GPU。

    • 直接寫在設定檔的 GPU 需求。 在資源精靈的容器資源設定中選定 GPU 型號。 平台會把它計入配額、比對計畫允許的 GPU 型號，並在部署時準備好 GPU。
    • 可重複使用的 GPU claim。 在資源精靈中選 部署時選保留 claim，並為 slot 取一個名稱 （例如 train-a）。slot 名稱只是標籤，實際要用 GPU Claims 標籤中的哪個 claim，由你在部署對話框中指定。

    Deployment 的所有 replica 共用同一個 claim。若只有部分 replica 要用 claim，請拆成多個 Deployment。 完全沒有要 GPU 的設定檔不需要型號清單，也不會被掛上 GPU claim。

    進階：自行撰寫 YAML

    平台自行管理的欄位請不要寫進 YAML：metadata.namespace、metadata.generateName、 metadata.ownerReferences、metadata.finalizers 都交給平台產生。 儲存請用 {{userVolume}} 掛載自己的個人儲存空間；直接寫出儲存空間名稱只有在群組專案、 且該群組本來就擁有那個儲存空間時才有效。

    • 直接寫的 GPU 需求放在容器的資源需求裡，例如 nvidia.com/rtx6000: "1"。
    • GPU claim slot 是加在 Pod 或 Deployment 範本上的註記： platform-go/dra-claim-name: '{{ gpuClaimName "train-a" }}'。 不帶名稱的 {{gpuClaimName}} 仍可作為預設 slot。多個工作負載可以刻意共用同一個 slot， 或用不同 slot 對應不同 claim。

    設定檔與部署需要專案管理者角色

    只有專案中擁有 管理者 以上角色的成員才能建立、編輯、部署、驗證、查看或刪除設定檔實例。

    管理成員¶

    1. 開啟專案並前往 成員 標籤。
    2. 點 + 新增成員（需要 專案管理員 角色）。
    3. 以使用者名稱或電子郵件搜尋使用者。
    4. 為每位使用者選擇角色：
    角色 可執行操作
    使用者 啟動工作區、查看設定
    管理者 編輯設定、管理部署
    管理員 新增/移除成員、設定成員配額
    1. 點 確認 儲存。

    Project Admin 可以一次勾選多位成員，批次移除、變更角色或設定個別配額。Manager 與 Admin 看得到所有人的配額，Project User 只看得到自己的。個別配額填 0 代表該資源不設個人上限，但仍受專案計畫總配額限制。

    透過群組加入的成員。 這類成員可以納入批次配額設定，但不能批次移除或批次變更角色；他們的成員身分與角色要回到群組層級調整。

    移除直接加入的成員時，平台也會清掉該成員在此專案中的工作區、儲存權限覆蓋與個別配額。透過群組繼承的成員必須從群組層級移除。

    群組繼承與有效專案角色¶

    群組擁有的專案上，平台依下列順序決定使用者的有效專案角色：

    1. 若使用者有明確的專案成員記錄，採用該角色（admin / manager / user）。
    2. 否則，若是個人專案，個人擁有者 視為 admin。
    3. 否則，採用該使用者在擁有群組中的角色 作為有效專案角色。因此 Group Admin 對該群組下的所有專案都等同於 Project Admin，即使沒有被直接加入專案。

    這也是為什麼 Group Admin 可以直接對群組擁有的專案設定成員個別配額，並且在成員標籤看到批次勾選介面，不需要先被加為該專案的直接成員。

    離職下架技巧：有人離開實驗室時，請管理員直接把他從對應的 群組 移除。所有以群組身分加入的專案存取會自動消失，不需要逐一專案移除。

    刪除專案¶

    只有平台管理員能刪除專案，位置在 管理 → 專案；專案頁面上沒有刪除功能。請找管理員或送一筆申請，並先刪掉專案的工作區。影響：

    • 設定檔版本歷史與部署記錄永久消失。
    • 儲存空間不會被刪除（仍保留在儲存頁）。

    資源標籤¶

    資源 標籤依專案成員彙整即時使用量：

    欄位 說明
    使用者 專案成員
    GPU 目前使用中的有效 GPU 單位
    CPU CPU 核心數
    Memory 記憶體 MiB
    Pod（執行中的實例） 該成員目前執行中的數量

    Project Admin、Project Manager 與平台 Admin/Manager 可以看到所有成員，一般 Project User 只會看到自己的資源列。展開該列可以檢查執行中的資源，並終止你有權管理的項目；終止工作負載後，它占用的配額會被釋放。

    在 Pod 那一列，將游標移到狀態徽章上（或點一下）可以看到最近的事件。當工作負載看起來一直在啟動、實際上卻是拉取映像失敗時，這裡就能看出原因。

    GPU 配額概覽¶

    總覽標籤顯示各資源類型的配額長條：

    資源 追蹤內容
    GPU 已消耗的有效 GPU 單位 vs. 計畫上限
    CPU 執行中工作區消耗的 CPU 核心數
    記憶體 執行中工作區消耗的 RAM

    若 GPU 長條已滿（100%），新的工作區啟動將排入佇列等待資源釋放。

    常見問題¶

    看不到新建專案按鈕。

    該按鈕只會顯示給具備 manage-projects 權限的使用者。若你沒有這項權限，請管理員幫你建立專案。你的個人專案在帳號建立時就已自動產生。

    如何查看舊版設定檔？

    在 設定 標籤中，點任何設定檔旁的時鐘圖示（歷史），即可查看所有過往版本與其時間。

    我的專案 GPU 配額為 0，如何取得更多？

    透過 申請 提交資源申請。管理員審核後會將資源計畫繫結到你的專案。

    工作區的 GPU 與 GPU Claim 有什麼不同？

    工作區的 GPU 只在該工作區存在期間保留。GPU Claim 則是獨立存在、跨越多次部署的保留。當多個工作需要共用同一份 GPU 切片、又想避免重新排程時很有用。

    為什麼部署按鈕被停用？

    可能是專案沒有綁定有效計畫，或計畫時段目前已關閉、僅能選擇預設佇列。請查看 計畫 標籤了解下一個時段開啟時間。
