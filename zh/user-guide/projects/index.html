    專案¶

    資源都掛在專案下。工作區用專案的配額，config file 和部署也都屬於某個專案。

    適用對象： 所有登入的使用者。建立帳號時會自動幫你開一個個人專案。

    專案頁面布局¶

    圖 1：專案列表，預設為列表模式。

    專案頁面有兩種檢視：

    • 列表模式（預設）：精簡的表格，欄位可排序
    • 卡片模式：卡片上有專案名稱、描述、成員數和 GPU 使用量長條

    用工具列右上角的圖示切換。

    建立專案¶

    要有 manage-projects 權限才能建立專案。沒有的話看不到 新建專案 按鈕，直接開建立頁面也會被導回專案列表，請管理員幫你建。個人專案在帳號建好時就開好了。

    1. 點左側選單的 專案。
    2. 點 新建專案（右上角）。
    3. 填寫專案表單：
    欄位 說明
    名稱 簡短的英數識別碼（可用連字號）
    群組 專案所屬的群組（必填）
    描述 選填，寫專案的用途
    1. 點 建立。專案馬上會出現在你的列表裡。

    配額由管理員指派

    新專案的 GPU 配額是 0。找管理員，或送一筆 申請，請管理員把資源計畫加到專案上。

    專案詳情分頁¶

    點專案進入專案頁。總覽、設定、計畫、建置、GPU Claims 和資源分頁每個人都看得到；平台開了 Ray 工作階段時會多一個 Ray 分頁；成員、儲存、設定分頁要看你的專案角色。

    圖 2：專案詳情分頁。

    分頁 內容
    總覽 描述、配額使用圖表、GPU 時數額度、目前的計畫、成員摘要
    配置 有 version control 的 config file，寫你要部署的內容
    計畫 專案的資源計畫、計畫時段、允許的 GPU 型號和配額範圍
    建置 專案的映像建置：選來源、看共用佇列狀態、讀即時建置日誌
    GPU Claims 先建立、之後再掛到部署上的 GPU 保留
    資源 你在跑的東西，依類別分頁（Pods、Services…），以及即時 GPU、CPU、記憶體用量；管理者還看得到每位成員的
    Ray 你的 Ray 工作階段，或提交 Ray 工作要用的位址；平台有開 Ray 工作階段才會出現
    成員 / 儲存 依角色顯示：管理成員、個別配額或儲存權限
    設定 專案內所有工作區的限制，見下方「專案設定」

    誰看得到什麼：儲存、設定 分頁要 Project Manager 以上；成員 分頁只有 Project Admin 看得到（平台管理員要在右上角頭像切到 Admin View，才算 Project Admin）。Admin 不能把自己降級，所以專案至少會留一位 Admin。

    專案設定¶

    設定 分頁（Project Manager 以上）放專案內所有工作區共用的限制，以及專案的 Docker Hub 連線：

    欄位 作用
    Workspace 最長連續使用時間 單位是秒。工作區執行超過這個時間就會自動停止。0 是不限制（預設）。
    Docker Hub 私有 Docker Hub 映像用的 username 和 access token。見下方「使用私有 Docker Hub 映像」。

    點 儲存變更 才會生效。這個上限也套用在這個專案啟動的 GPU 桌面。

    建置專案映像¶

    專案要自己的映像，就用 建置 分頁。Dockerfile 的 FROM base image 可以來自任何 registry，平台會自動掃描安全問題，不用核准。專案開啟映像建置後，專案管理者和專案管理員可以啟動建置。一般成員只能看狀態和日誌，或刪除自己啟動、已完成的建置映像。

    來源模式¶

    來源 使用時機
    上傳 archive 上傳 .tar.gz 或 .zip，Dockerfile 要放在最上層
    只貼 Dockerfile 直接貼上 Dockerfile，其他的由平台準備

    建置設定¶

    欄位 說明
    映像名稱 短名稱，例如 trainer-api；完整映像路徑由平台產生
    Tag 選填；留空用平台預設，也可填 v1.0.1 這類版本
    建置來源 上傳 archive，或直接貼 Dockerfile

    建置會排進共用佇列，一次只跑一個。每個建置的 CPU、記憶體和暫存空間是固定的，表單裡不能調整，也不會用掉專案或個人的配額。

    一段時間沒人建置，建置環境會自動關閉，送出建置時才會啟動，所以第一個建置要多等約一分鐘。排隊中的建置會顯示在等什麼；建置環境或暫存空間 20 分鐘內沒準備好，建置會失敗並寫出原因。建置開始前，平台會檢查壓縮檔的路徑安全和檔案大小。

    建置跑不完時，會直接失敗並顯示下列訊息，不會一直等：

    訊息 意思
    Build pod cannot start: \<原因> 建置找不到地方執行，或映像拉不下來。晚點再送一次。
    Build did not start within N minutes. \<等待訊息> 建置環境或暫存空間在時限內沒準備好，等待訊息會寫是哪一個。晚點再送一次。
    Build did not finish within N minutes 建置超過時間上限。
    The build's Kubernetes Job was removed before it reported a result 建置被外部中止。重新送出即可。

    建置歷史列出狀態、來源類型、目的映像和即時日誌。建置失敗時，表格只有簡短摘要，完整錯誤點那一列的日誌按鈕看。重試的話，日誌畫面會留著上一次的失敗原因。

    每筆建置有幾個圖示按鈕：執行中可以 取消建置（已經產出映像的則是 刪除映像 artifact）、清除保存日誌、刪除歷史紀錄。

    • 清除保存日誌：建置者和專案管理者可以清除已完成或失敗建置的保存日誌，建置歷史和映像不會動到。
    • 刪除映像 artifact：啟動那次建置的成員本人或專案管理者可以刪。
    • 清空我的已完成建置映像：刪除你在這個專案建的所有已完成映像，建置歷史和保存日誌會留著。重複的 tag ID 只會刪一次。
    • 刪除歷史紀錄：只移除歷史和保存日誌，不會刪除映像 artifact。映像倉庫每天做一次 garbage collection 才會釋放空間，剛上傳的映像可能要等兩次才清得掉。

    我的映像¶

    側邊欄的 我的映像 列出你在所有專案建過的映像：映像與 tag、專案、大小、digest、安全檢查 和推送時間。點刪除圖示再確認，就會刪掉該映像。要執行的話，見 在工作區執行建置映像。

    config file 的 image 欄位會在你輸入時建議專案已建置的映像，你仍可以填任何映像。

    建置權限由專案治理控制

    看不到建置表單，代表專案沒開 映像建置權限，或你的專案角色不能啟動建置。歷史和日誌還是看得到。要調整的話，找專案管理者或平台管理員。

    GPU Claims¶

    GPU Claims 分頁列出你在部署前先建立的 GPU 保留，claim 的定義見 GPU Claim。config file 有 GPU claim slot 的話，在部署對話框裡選要用哪個 claim。

    建立 Claim¶

    這個分頁和表單在介面上是英文。填好 Create GPU ResourceClaim 表單，點 Create：

    欄位 說明
    Claim name 掛到部署上時用的名稱，只能用英數字和連字號。
    GPU device class 要保留的 GPU 型號。表單一開始選了一個型號，不在意型號才選 Any。
    GPU count 這個 claim 保留幾張實體 GPU；多張 GPU 仍算同一筆保留。
    SM share 1% 到 100% 的算力比例；表單旁會顯示對應的有效 GPU 數量。
    VRAM mode Elastic 和其他工作負載共用顯示記憶體；Hard cap 則嚴格照你選的比例。
    VRAM share 只在選 Hard cap 時有效，依這個型號最小的那張卡算保留量。

    Deployment 的所有 replica 共用同一個 claim，所以 2 張 GPU 的 claim 不管跑幾個 replica，都是同一筆 2-GPU 保留。配額和 GPU 時數每個 claim 只算一次，不是每個 replica 各算一次。

    還沒使用的 claim，GPU 時數是 0，但仍佔用專案和個人的 GPU 配額。Status 有三種：Reserved（已建立，還沒掛任何東西）、Allocated（已配到 GPU）、In use by <部署名稱>。沒在用的 claim 可以刪除，執行中的工作負載正在用的不行。

    Claim 擁有權

    專案成員可以建立自己的 claim。專案管理者還能看到並刪除其他成員建的 claim。

    計畫時段倒數¶

    計畫 分頁用台灣時間（UTC+8）分開顯示排程和優先時段的倒數。能不能啟動工作，一律看 排程時段。兩種時段怎麼運作，見計畫時段。

    • 時段將於以下時間關閉 HH:MM:SS 是你還剩多少時間。
    • 時段將於以下時間開啟 HH:MM:SS 是多久後又能啟動工作。
    • 永遠啟用 表示沒有每週排程限制。

    排程快關閉時，部署對話框會提醒你。關閉後不能送出新部署，換佇列也沒用。已經在跑的工作依計畫的停止政策處理。

    計畫有 Burst 時段 的話，會另外顯示 優先時段結束於 HH:MM:SS 或 優先時段開始於 HH:MM:SS，只算它和排程時段重疊的部分。只有在重疊的時間裡，優先佇列才會和一般佇列一起出現。Burst 結束不會停掉已在跑的工作，也不會關閉排程。還在優先佇列上的部署怎麼處理，見計畫時段。部署對話框開著時如果時段變了，佇列選項會自動更新：還能選的會保留，過期的驗證結果會清掉。

    管理員可以替佇列設執行時間上限。你選的佇列有上限的話，工作負載到時間就會自動停止，通知鈴鐺會收到「已達執行時間上限」。config file 裡不能提高或關掉這個上限。

    計畫有 GPU 時數額度的話，總覽 分頁會多一條 GPU 時數 長條，顯示本期用量和額度。旁邊有重設週期（每月、每週或每 N 小時，由管理員設定）和下次重設時間（UTC+8）。額度用完後，要等重設才能啟動新的 GPU 任務和工作區，執行中的不受影響。

    專案可以執行的映像¶

    專案建置的映像只有這個專案的成員看得到，其他專案不能跑，你也不能跑別的專案的。專案可以執行：

    • 自己建置的映像；
    • 平台提供的映像，例如現成的 IDE 與桌面映像；
    • Docker Hub、GHCR 與 NVIDIA NGC 的公開映像，由平台代理拉取；
    • 建置改為各專案私有之前建置的舊映像：你自己建置的只能在你的個人專案使用，群組建置的只能在該群組擁有的專案使用。

    任務或工作區用了別的專案建置的映像時，映像安全檢查 卡片會顯示 錯誤 的一列，原因是 Image security check refused: <ref>: built by another project; use this project's images, platform images or public mirrors。請在自己的專案重新建置，或請映像所屬的專案分享 Dockerfile。Dockerfile 的 FROM 也一樣：base image 屬於別的專案，建置會被拒絕。

    使用私有 Docker Hub 映像¶

    由 Project Manager 替整個專案連一次 Docker Hub 帳號：

    1. 在 Docker Hub 開啟 Account settings → Personal access tokens，建立權限為 Read-only 的 token。
    2. 在專案開啟 設定 → Docker Hub 帳號，填入 使用者名稱 和 Access token，按 儲存。平台會先向 Docker Hub 驗證，不對就拒絕並顯示 Docker Hub could not be reached with this username and token。
    3. 照一般方式使用：在任務、部署或工作區寫 image: <user>/<repo>:<tag>，或在專案的 IDE 裡 docker run。

    連線後，這一區會顯示 已連結帳號 <username>，於 <time> 更新。token 不會再顯示；要更換就重新儲存一個。移除 會先確認，再中斷連線並刪除專案已快取的私有映像。公開的 Docker Hub 映像不受影響。Dockerfile 的 FROM 也可以用私有 Docker Hub 映像。

    成員在 IDE 執行過 docker login 的話，那是他個人的 Docker Hub 登入，平台會先用它，再用專案帳號。見私有 Docker Hub 映像。

    私有映像一樣會做安全檢查，而且只有這個專案能用。專案內任何成員的工作負載都能拉取該帳號的所有私有映像，請連專為專案準備的帳號和 token。

    映像安全檢查¶

    總覽 分頁的 映像安全檢查 卡片，列出專案的任務與工作區最近啟動的 10 個映像，以及各自的狀態：

    狀態 意義
    檢查中 平台還在檢查這個映像。卡片會自動更新。
    通過 映像可以執行。
    未通過 映像裡有套件不適合在這裡執行，平台已擋下。
    錯誤 檢查無法完成，例如映像或 tag 不存在，或檢查逾時。
    不支援 映像來自平台無法檢查的 registry。

    只有映像裡的套件危及平台時，平台才會擋下。你自己 container 內的已知弱點不會擋。每一列還有一行原因和最後使用時間。平台關閉映像檢查時，卡片會顯示「映像安全檢查已關閉。」

    點 未通過 的列可看要升級什麼：每個造成封鎖的套件、你目前的版本與要升級到的版本。畫面不顯示弱點編號，只有管理員看得到。其他狀態沒有可展開的詳細內容。

    未通過 的訊息是：<image>: blocked by the platform because <package> <version> is unsafe to run here. Upgrade it to <fix version> or later (rebuild on a newer base, or pick a newer tag)。錯誤 的列也可能寫映像在 Docker Hub 找不到，或該 registry 不支援，請改用 Docker Hub、GHCR、NGC 或這個專案的映像。

    要修正，就換較新的基底映像標籤重建，或在 Dockerfile 用 apt、apk、dnf、pip 把列出的套件升到修補版本以上，再重跑任務。公開映像（例如 Docker Hub 的）改用較新的標籤。平台映像改選其他版本，或找管理員。

    卡片只顯示每個映像的最新結果，不是歷史紀錄。用到第 11 個映像時，最舊的一列會被擠掉。

    Config file version control¶

    每次儲存都會產生新版本，舊版本不會被覆蓋。你可以查看任何舊版本，也可以重新部署它。

    操作 config file¶

    1. 前往 專案 → [你的專案] → 設定 分頁。
    2. 點 新增檔案，上傳 YAML 檔案，或在編輯器貼上內容。
    3. 點設定旁的 歷史記錄 圖示查看所有版本。
    4. 要部署特定版本，點版本列的 部署 按鈕。
    5. 在部署對話框選排程佇列。YAML 有 GPU claim slot 的話，替每個 slot 選一個你已保留的 GPU claim，只對這次部署有效。

    執行中的項目會出現在專案的 資源 分頁，說明在下方。

    已結束的 Pod 最多留三天，之後平台會移除它，資源 分頁上的項目和日誌也一起消失。日誌可能更早就不見，例如節點重新開機。Job 結束後，它的 Pod 會留到你刪除這個 Job 為止。要留的結果，跑的時候就寫進掛載的儲存空間。

    可以進去操作的容器¶

    要開 終端，容器得一直在跑。只跑 Shell、不帶參數（例如 command: ["/bin/sh"]）會馬上結束，容器一直重啟，每次開終端都會失敗。

    讓容器有事做：

    command: ["sleep", "infinity"]

    或在資源精靈的 互動式 Shell 區塊勾選 stdin 和 tty（手寫 YAML 則是 stdin: true 和 tty: true），讓 Shell 保持執行。精靈發現單獨的 Shell 會馬上結束時，會跳出警告。

    容器啟動後，到專案的 資源 分頁，留在 Pods，在那一列點 終端。Deployment 和 Job 沒有終端按鈕，它們建立的執行中項目在 Pods 裡。

    部署規則¶

    配額算的是你所有還沒結束的工作，排隊等啟動的也佔配額，直到結束或移除。config file 可以部署 Pod、Deployment 和 Job，其他類型不接受。

    每個容器都要同時設定記憶體的 request 和 limit，而且至少 128Mi。少了任何一項，部署和 dry-run 驗證都會被拒絕。單位一定要寫：只寫 memory: "1" 是 1 byte，會被拒絕。

    要 GPU 的兩種方式¶

    • 直接寫在 config file 的 GPU 需求。 在資源精靈的容器資源設定選 GPU 型號。平台會把它算進配額、檢查型號在不在計畫允許的範圍內，並在部署時準備好 GPU。
    • 可重複使用的 GPU claim。 在資源精靈選 部署時選保留 claim，幫 slot 取個名稱（例如 train-a）。slot 名稱只是標籤。要用 GPU Claims 分頁裡的哪個 claim，在部署對話框裡指定。

    只有部分 replica 要用 claim 的話，請拆成多個 Deployment。完全不要 GPU 的 config file 不需要型號清單，也不會掛上 GPU claim。

    進階：自行撰寫 YAML

    這幾個欄位由平台管理，不要寫進 YAML：metadata.namespace、metadata.generateName、 metadata.ownerReferences、metadata.finalizers。 儲存請用 {{userVolume}} 掛載自己的個人儲存空間。直接寫儲存空間名稱，只有在群組專案、 而且該群組本來就有那個儲存空間時才行。

    • 每個 Pod 有一個 /dev/shm，放在記憶體裡，由一般容器共用（不含 init 容器），最大 8 GiB；Pod 的記憶體上限比 8 GiB 小的話，就以上限為準。只要有任何容器已經在 /dev/shm 底下掛了東西，就不會再加。
    • 直接寫的 GPU 需求放在容器的資源需求裡，例如 nvidia.com/rtx6000: "1"。
    • GPU claim slot 是加在 Pod 或 Deployment 範本上的註記： platform-go/dra-claim-name: '{{ gpuClaimName "train-a" }}'。 不帶名稱的 {{gpuClaimName}} 仍是預設 slot。多個工作負載可以故意共用同一個 slot， 也可以用不同 slot 對應不同 claim。

    config file 與部署需要專案管理者角色

    只有專案裡 管理者 以上角色的成員，才能建立、編輯、部署、驗證、查看或刪除 config file 的項目。

    管理成員¶

    1. 開啟專案，進 成員 分頁。
    2. 點 + 新增成員（需要 專案管理員 角色）。
    3. 用使用者名稱或電子郵件搜尋。
    4. 幫每個人選角色：
    角色 可執行操作
    使用者 啟動工作區、查看設定
    管理者 編輯設定、管理部署
    管理員 新增/移除成員、設定成員配額
    1. 點 確認 儲存。

    Project Admin 可以一次勾選多位成員，批次移除、變更角色或設定個別配額。Manager 和 Admin 看得到所有人的配額，Project User 只看得到自己的。個別配額填 0 是這項資源不設個人上限，但專案計畫的總配額仍然有效。

    透過群組加入的成員。 這類成員可以一起做批次 配額 設定，但不能批次 移除 或 變更角色，請到群組去改。

    移除直接加入的成員時，平台也會清掉他在這個專案的工作區、儲存權限覆蓋和個別配額。透過群組加入的成員，要從群組移除。

    群組繼承與有效專案角色¶

    專案屬於群組時，平台依序判斷你的專案角色：

    1. 如果你是直接加入專案的，就用那個角色（admin / manager / user）。
    2. 否則，個人專案的擁有者算 admin。
    3. 否則，用你在擁有群組裡的角色當專案角色。所以 Group Admin 在群組擁有的所有專案裡都等於 Project Admin。

    所以 Group Admin 不用先被加進專案，就能替群組的專案設定成員個別配額，也看得到成員分頁的批次勾選。

    有人離開實驗室時：請管理員把他從對應的 群組 移除。他透過群組加入的所有專案，存取權都會一起消失，不用一個個專案處理。

    刪除專案¶

    只有平台管理員能刪除專案，在 管理 → 專案 操作，專案頁上沒有刪除按鈕。請找管理員，或送一筆 申請；專案的工作區要先刪掉。刪除後：

    • config file 的版本歷史和部署記錄會永遠消失。
    • 儲存空間不會被刪除，還在儲存頁。

    資源分頁¶

    資源 分頁顯示專案裡在跑什麼、用了多少。

    你自己的資源。 上方的卡片是你的 GPU、CPU、記憶體用量。下面依類別分頁：Pods、Services、Deployments、StatefulSets、Jobs、ConfigMaps、Secrets、Ingresses、ResourceClaims、RemoteDesktopSessions，每個分頁標著數量，預設開在 Pods。暫停中的工作列在 Pods 最上方，因為恢復前它沒有 Pod。按 全部刪除 會刪掉你在這個專案的所有資源，佔用的配額也會釋放。

    所有人的資源。 Project Admin、Project Manager 和平台 Admin/Manager 會在分頁上方看到 個人 和 成員。成員 列出其他所有成員：

    欄位 說明
    使用者 專案成員
    GPU 目前使用中的有效 GPU 單位
    CPU CPU 核心數
    Memory 記憶體 MiB
    Pod（執行中的項目） 該成員目前在跑的數量

    可以用名字搜尋，展開成員就能用同樣的類別分頁看對方在跑什麼。在成員那一列按 刪除，會刪掉該成員所有的資源並釋放配額。一般 Project User 只看得到自己的資源。

    在 Pod 那一列，把游標移到狀態徽章上（或點一下）就能看到最近的事件。工作負載一直卡在啟動，其實是拉不到映像時，從這裡看得出原因。

    GPU 配額概覽¶

    總覽分頁顯示各資源類型的配額長條：

    資源 追蹤內容
    GPU 已消耗的有效 GPU 單位 vs. 計畫上限
    CPU 執行中工作區用掉的 CPU 核心數
    記憶體 執行中工作區用掉的 RAM

    GPU 長條滿了（100%），新的工作區就要在佇列裡等資源釋放。

    常見問題¶

    看不到新建專案按鈕。

    只有具備 manage-projects 權限的使用者看得到這個按鈕。沒有的話，請管理員幫你建立專案；你的個人專案已經開好了。

    如何查看舊版 config file？

    在 配置 分頁，點 config file 旁的時鐘圖示（歷史記錄），就能看到所有舊版本和時間。

    我的專案 GPU 配額為 0，如何取得更多？

    送一筆 申請。管理員審核後，會把資源計畫加到你的專案。

    工作區的 GPU 與 GPU Claim 有什麼不同？

    工作區的 GPU 只在工作區存在時保留。GPU Claim 是獨立的保留，可以跨多次部署。多個工作要共用同一份 GPU 切片、又不想每次重新排程時，就用它。

    為什麼部署按鈕被停用？

    可能是專案沒有有效的計畫，或排程時段現在關閉了。預設佇列也一樣不行。到 計畫 分頁看下一個時段什麼時候開。
