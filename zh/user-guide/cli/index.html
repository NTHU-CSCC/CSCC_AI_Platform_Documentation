    命令列工具¶

    用 cscc-cli 在終端機登入平台、建置映像檔、看建置日誌、在 IDE 裡使用 docker 指令，以及管理你的 API token。

    適用對象： 所有登入的使用者。

    登入¶

    新機器第一次用時，請用 --api-url 或 CSCC_API_URL 指定 API URL。URL 可以帶 /api/v1，CLI 會自己處理。

    cscc-cli login --api-url https://api.cscc.nthu.edu.tw --username alice

    CLI 會問你密碼。跟儀表板不同，這裡不需要驗證碼。

    登入後，CLI 會把 cscc_... API token 存在你電腦上的設定檔，只有你能讀。token 本身只在建立時顯示一次。

    要幫 token 取名：

    cscc-cli login --api-url https://api.cscc.nthu.edu.tw --username alice --name workstation

    token 名稱最多 100 個字元。不加 --name 的話，名稱是 cscc-cli。

    匯入由儀表板建立的 token¶

    你也可以在儀表板的 設定 → API Key & CLI 建立 API token，再匯入 cscc-cli：

    cscc-cli login --api-url https://api.cscc.nthu.edu.tw --token cscc_...

    CLI 會先驗證 token，通過才會存起來。已經在儀表板登入、不想在終端機再打密碼時，用這個方法。

    無狀態 token 覆寫¶

    寫腳本時，用 CSCC_API_TOKEN 就不用存設定檔：

    CSCC_API_URL=https://api.cscc.nthu.edu.tw CSCC_API_TOKEN=cscc_... cscc-cli whoami

    CSCC_DEV_TOKEN 還能用，但已淘汰。新腳本請用 CSCC_API_TOKEN。

    TLS / 內部 CA¶

    官方 cscc-cli 已內建平台憑證，通常不用另外設定。如果平台換了憑證，請先下載最新版 CLI 再連線。

    下面的環境變數只在自己編譯 CLI 或排查 TLS 問題時才需要：

    環境變數 說明
    CSCC_API_URL API base URL，例如 https://api.cscc.nthu.edu.tw/api/v1
    CSCC_API_TOKEN 選用的無狀態 cscc_... token 覆寫
    CSCC_API_CA_CERT_PATH 一個或多個 PEM 檔路徑，可用 , 或 ; 分隔
    CSCC_API_TLS_SERVER_NAME 選用 TLS SNI 名稱；未設定時使用 config fallback
    SSL_CERT_FILE 包含內部 root CA 的 PEM 檔路徑
    REQUESTS_CA_BUNDLE 另一個 PEM bundle 路徑環境變數

    範例：

    CSCC_API_CA_CERT_PATH=/Users/me/platform-internal-root-ca.pem \
  cscc-cli login --api-url https://api.cscc.nthu.edu.tw --username alice

    確認身分¶

    cscc-cli whoami

    這會驗證你存的 token，並印出目前的使用者和角色。角色一改就馬上生效。

    建置映像檔¶

    預設是 upload 模式，可以給資料夾、.tar.gz 或 .zip：

    cscc-cli build --project <project-id> --name trainer --tag v1.0.1 .
cscc-cli build --project <project-id> --name trainer ./context.tar.gz

    給資料夾的話，CLI 會幫你打包成 .tar.gz。不管哪種，Dockerfile 都要放在最上層。

    Dockerfile-only 模式就像在儀表板貼上 Dockerfile：

    cscc-cli build --source dockerfile \
  --project <project-id> \
  --name trainer \
  --tag v1.0.1 \
  --dockerfile ./Dockerfile

cat Dockerfile | cscc-cli build --source dockerfile \
  --project <project-id> \
  --name trainer \
  --dockerfile -

    選項：

    選項 說明
    --project 這個映像檔建置所屬的專案 ID
    --name 簡短映像檔名稱，例如 trainer-api
    --tag 選用映像檔 tag；省略時使用平台預設值
    --source upload 或 dockerfile
    --dockerfile --source dockerfile 時的 Dockerfile 路徑，或用 - 讀 stdin
    --build-arg Dockerfile ARG 覆寫，格式 KEY=VALUE；可重複使用
    --follow=false 只提交建置，不串流日誌

    建置參數（build arguments）¶

    用 --build-arg KEY=VALUE 在建置時傳入 Dockerfile 的 ARG。要傳多個就重複這個旗標，upload 和 dockerfile 建置都能用。KEY 要以英文字母或底線開頭，只能有英文字母、數字和底線。

    cscc-cli build --project <project-id> --name trainer --tag v1 \
  --build-arg HF_TOKEN=hf_xxx \
  --build-arg MAX_JOBS=4 \
  .

    可以用來把密鑰和參數留在 Dockerfile 外面（例如 ARG HF_TOKEN），或壓低編譯的並行數（MAX_JOBS、FLASH_ATTN_MAX_JOBS …），讓大型建置塞得進共用的建置環境。

    看得到該次建置的人都看得到 build-arg，別放太敏感的內容；用這個方式傳的 token，建置完請換掉。

    共用建置佇列¶

    所有人共用同一套建置環境，一次只跑一個建置。每個建置的 CPU、記憶體和暫存空間是固定的，你不能調整。

    一段時間沒人建置，建置環境就會自動關閉。之後的第一個建置要多等約一分鐘讓它啟動。

    提交後，--follow=true（預設）會等日誌出現再顯示，建置回報 completed、failed 或 deleted 時就停止。

    CLI 取得 API 位址的順序是：登入時的 --api-url、CSCC_API_URL、已儲存的設定：

    export CSCC_API_URL=https://api.cscc.nthu.edu.tw

    建置和日誌都用 cscc-cli login 建立的 token，不需要其他憑證。專案必須開啟 Image Build Permission，你的專案角色也要允許建置。

    在 IDE 裡使用 docker¶

    你的 Jupyter 和 code-server 工作區有 docker 指令。用法和 Docker 很像，但每個容器都是叢集上的任務，並掛載你的檔案。工作區裡不會執行任何容器。

    只要登入一次。工作區已經知道 API URL 和你的專案：

    cscc-cli login --username alice

    接著照 Docker 的用法：

    docker run pytorch/pytorch:latest python train.py
docker run --gpus 1 -m 16g -w /home/alice/exp pytorch/pytorch:latest python train.py
docker run -d --name sweep python:3.12 python sweep.py
docker logs -f <job-id>
docker build -t myimg .

    輸出會即時顯示在終端機。任務成功時指令回傳 0，失敗時回傳 1。按 Ctrl-C 只是停止觀看，任務會繼續跑；要停止任務，用 docker rm <job-id>。

    指令 作用
    docker run [選項] IMAGE [COMMAND] 啟動任務。加 -d 會印出任務 ID 並立刻返回
    docker ps [-a] 列出執行中的任務；-a 連已結束的一起列出
    docker logs [-f] [--tail N] <job-id> 顯示任務輸出
    docker rm、stop、kill <job-id> 停止任務
    docker build -t NAME[:TAG] [CONTEXT] 用資料夾最上層的 Dockerfile 建置映像

    docker run 選項：

    選項 說明
    -d 不等待，印出任務 ID
    -e KEY=VALUE 設定環境變數；可重複使用。不要用它傳密鑰
    -w DIR 工作目錄。預設是目前所在、位於 /home 或 /mnt/shared 下的資料夾
    --cpus N CPU 核心數
    -m、--memory 記憶體，例如 512m 或 4g
    --gpus N GPU 數量。不能用 --gpus all，請給數字
    --name、--queue 任務名稱和排程佇列
    --project 專案。預設是你工作區所屬的專案
    -u UID 數字使用者 ID。-u 0 以 root 執行，專案要允許 root
    --rm 接受但不處理，結束的任務由平台清理

    專案裡的其他成員看得到你用 -e 傳入的值。不要傳 token、密碼或金鑰，把它們放在家目錄的檔案裡，再在指令中讀取。

    和 Docker 的差異¶

    • 任務以和工作區相同的使用者執行，所以它寫在家目錄的檔案，仍然可以在 IDE 裡編輯。只有在需要 root 而且專案允許時，才用 -u 0。
    • 任務在叢集上執行，不在你的工作區。CPU、記憶體和 GPU 由你傳入的選項和專案配額決定。
    • 你的家目錄和群組儲存空間掛載在和工作區相同的路徑，所以 python /home/alice/exp/train.py 會讀到同一個檔案。沒有 -v。
    • 任務啟動前，平台會檢查每個映像的安全性。第一次使用新映像時要等這項檢查。
    • 沒有連接埠、沒有互動式終端機（-i、-t），也沒有 --privileged 和 --network。需要互動操作時，請用工作區的終端機。
    • 沒有 docker pull、push、images、exec 和 compose。平台會在任務啟動時取得映像，docker build 會替你發佈映像。它和 cscc-cli build 一樣，需要專案開啟 Image Build Permission。

    疑難排解¶

    • 指令印出 waiting: image security check / scheduling。 任務還沒開始。新映像要等安全檢查，佇列忙碌時則要等資源。任務開始後才會有輸出，指令可以一直開著。
    • 任務顯示 failed 而且沒有輸出。 映像可能沒通過安全檢查。用 docker ps -a 看狀態，並詢問你的專案管理者。
    • no project。 請在工作區裡執行，或加上 --project <project-id>。
    • API URL is required 或驗證錯誤。 重新執行 cscc-cli login。

    Token 管理¶

    列出你有效的 API token：

    cscc-cli tokens list

    用 token ID 撤銷 token：

    cscc-cli tokens revoke <token-id>

    登出這台電腦：

    cscc-cli logout

    登出會撤銷你正在用的 token，並從設定檔移除。你手動設定的憑證選項會保留，下次登入不用重設。

    預設值¶

    設定 預設值 說明
    Token 有效期 90 天 到期後請重新建立一個
    每人有效 token 上限 20 達到上限時，請先撤銷不再使用的 token
    登入失敗鎖定次數 5 儀表板和 CLI 一起算
    鎖定時間 15 分鐘 等它解除，或請管理員解鎖

    管理員可以調整這些數值。
