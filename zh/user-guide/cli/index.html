    命令列工具¶

    cscc-cli 讓你在終端機登入平台、建置映像、看建置日誌、在 IDE 裡用 docker，以及管理 API token。

    適用對象： 所有登入的使用者。

    安裝¶

    工作區裡已經有 cscc-cli。要在自己的電腦上用，先從儀表板的設定 → 安全性 → 下載取得，再執行：

    chmod +x cscc-cli-linux-amd64
sudo mv cscc-cli-linux-amd64 /usr/local/bin/cscc-cli

    macOS 用 darwin 開頭的檔案；第一次執行被 macOS 擋下來的話，跑一次 xattr -d com.apple.quarantine /usr/local/bin/cscc-cli。Windows 把 cscc-cli-windows-amd64.exe 改名成 cscc-cli.exe，放到 Path 有列到的資料夾。

    登入¶

    新機器第一次用，要用 --api-url 或 CSCC_API_URL 指定 API URL（可以帶 /api/v1）。CLI 依序採用 --api-url、CSCC_API_URL、已儲存的設定。

    cscc-cli login --api-url https://api.cscc.nthu.edu.tw --username alice

    CLI 會問密碼，但不用輸入驗證碼。登入後 cscc_... API token 會存在你電腦上的設定檔，只有你能讀。token 只在建立時顯示一次。

    幫 token 取名：

    cscc-cli login --api-url https://api.cscc.nthu.edu.tw --username alice --name workstation

    名稱最多 100 個字元，不加 --name 就叫 cscc-cli。

    匯入由儀表板建立的 token¶

    在儀表板的 設定 → API Key 與 CLI 建立 API token，再匯入 cscc-cli：

    cscc-cli login --api-url https://api.cscc.nthu.edu.tw --token cscc_...

    CLI 驗證通過才會存。不想在終端機打密碼就用這個方法。

    無狀態 token 覆寫¶

    寫腳本用 CSCC_API_TOKEN，不用存設定檔：

    CSCC_API_URL=https://api.cscc.nthu.edu.tw CSCC_API_TOKEN=cscc_... cscc-cli whoami

    CSCC_DEV_TOKEN 還能用但已淘汰，新腳本用 CSCC_API_TOKEN。

    TLS / 內部 CA¶

    從下載取得的 cscc-cli 已內建平台憑證，通常不用設定。平台換憑證時，重新下載最新版。自己編譯 CLI 或排查 TLS 問題，才需要下面的環境變數：

    環境變數 說明
    CSCC_API_URL API base URL，例如 https://api.cscc.nthu.edu.tw/api/v1
    CSCC_API_TOKEN 選用的無狀態 cscc_... token 覆寫
    CSCC_API_CA_CERT_PATH 一個或多個 PEM 檔路徑，可用 , 或 ; 分隔
    CSCC_API_TLS_SERVER_NAME 選用 TLS SNI 名稱；未設定時使用 config fallback
    SSL_CERT_FILE 包含內部 root CA 的 PEM 檔路徑
    REQUESTS_CA_BUNDLE 另一個 PEM bundle 路徑環境變數 
    CSCC_API_CA_CERT_PATH=/Users/me/platform-internal-root-ca.pem \
  cscc-cli login --api-url https://api.cscc.nthu.edu.tw --username alice

    確認身分¶

    cscc-cli whoami

    驗證已存的 token，印出目前的使用者和角色。角色變更馬上生效。

    建置映像檔¶

    預設是 upload 模式，可以給資料夾、.tar.gz 或 .zip：

    cscc-cli build --project <project-id> --name trainer --tag v1.0.1 .
cscc-cli build --project <project-id> --name trainer ./context.tar.gz

    資料夾會自動打包成 .tar.gz。不管哪種，Dockerfile 都要放在最上層。

    Dockerfile-only 模式等於在儀表板貼 Dockerfile：

    cscc-cli build --source dockerfile \
  --project <project-id> \
  --name trainer \
  --tag v1.0.1 \
  --dockerfile ./Dockerfile

cat Dockerfile | cscc-cli build --source dockerfile \
  --project <project-id> \
  --name trainer \
  --dockerfile -
    選項 說明
    --project 這個映像檔建置所屬的專案 ID
    --name 簡短映像檔名稱，例如 trainer-api
    --tag 選用映像檔 tag；省略時使用平台預設值
    --source upload 或 dockerfile
    --dockerfile --source dockerfile 時的 Dockerfile 路徑，或用 - 讀 stdin
    --build-arg Dockerfile ARG 覆寫，格式 KEY=VALUE；可重複使用
    --follow=false 只提交建置，不串流日誌

    建置參數（build arguments）¶

    --build-arg KEY=VALUE 把值傳給 Dockerfile 的 ARG。要傳多個就重複寫，upload 和 dockerfile 建置都能用。KEY 要以英文字母或底線開頭，只能有英文字母、數字和底線。

    cscc-cli build --project <project-id> --name trainer --tag v1 \
  --build-arg HF_TOKEN=hf_xxx \
  --build-arg MAX_JOBS=4 \
  .

    可以把密鑰和參數留在 Dockerfile 外面（例如 ARG HF_TOKEN），或壓低編譯並行數（MAX_JOBS、FLASH_ATTN_MAX_JOBS …），讓大型建置塞得進共用的建置環境。

    看得到這次建置的人都看得到 build-arg，別放敏感內容；用這個方式傳的 token，建置完就換掉。

    共用建置佇列¶

    所有人共用同一套建置環境，一次只跑一個建置。每個建置的 CPU、記憶體和暫存空間固定，不能調整。

    一段時間沒人建置，環境會自動關閉，下一個建置要多等約一分鐘啟動。

    送出後，預設的 --follow=true 會等日誌出現再顯示，建置回報 completed、failed 或 deleted 就停止。

    建置和日誌都用 cscc-cli login 的 token，不需要其他憑證。專案要開啟 映像建置權限，你的專案角色也要能建置。

    在 IDE 裡使用 docker¶

    Jupyter 和 VS Code 工作區裡有 docker 指令，用法和 Docker 一樣。容器在工作區旁邊啟動，屬於同一個專案，計入專案配額；工作區本身不跑容器。

    登入¶

    平台更新後啟動的工作區不用登入，docker 直接用工作區的身分。更新前啟動的工作區維持舊行為：每個容器是獨立的任務，要用 cscc-cli login 登入，docker 會印出 restart your workspace for full docker support。刪掉工作區再啟動新的就好，儲存空間裡的檔案都還在。

    執行容器¶

    docker run --rm alpine echo hello
docker run -d --name web -p 8080:8000 python:3.12 python -m http.server 8000
curl localhost:8080
docker ps
docker logs -f web
docker stop web

    輸出會即時顯示在終端機，指令結束時回傳容器的結束碼。

    沒有 -t 時，Ctrl-C 和 Docker 的訊號轉送一樣。按第一次送 SIGINT 給主程序（映像要有 /bin/sh，沒有就直接停止容器）。按第二次停止容器（先 SIGTERM，10 秒後 SIGKILL）。按第三次脫離，容器在背景繼續停止。有 -t 時，Ctrl-C 直接交給容器裡的程式。

    docker run -d 會先顯示 Waiting: …，容器開始執行才印出 ID。容器啟動失敗會印出原因、移除容器，並以 125 結束。Ctrl-C 只停止等待，容器會繼續啟動。

    和 Docker 相同的地方¶

    • 容器裡只看得到你掛載的路徑，用 -v SRC:DST[:ro] 或 --mount type=bind,source=SRC,target=DST 掛載資料夾。相對路徑的 SRC 要寫 ./data 或 ../data，只寫 data 是具名 volume，這裡不支援。SRC 不存在時，-v 會建立，--mount 會失敗。
    • SRC 必須在你的家目錄或群組儲存空間底下。唯讀的儲存空間在容器裡也是唯讀。
    • 映像自己的 WORKDIR、ENTRYPOINT 和 CMD 都會生效。映像名稱後面的指令取代 CMD，--entrypoint 取代 entrypoint。
    • 沒有指定 -u 時，容器以映像宣告的數字 USER（例如 USER 101）執行。映像沒有宣告 USER，或只宣告名稱（例如 USER app）時，以使用者 1000 執行（和工作區相同），所以寫進儲存空間的檔案在 IDE 裡仍可編輯。-u 0 和宣告 USER 0 的映像，專案允許 root 容器時（群組專案還要群組允許）才會以 root 執行，否則仍是使用者 1000。
    • 沒指定 --cpus 和 -m 時，每個容器是 1 個 CPU、4 GiB 記憶體。--shm-size 設定 /dev/shm 的大小。
    • -e KEY=VALUE、-e KEY（複製你目前的值）、--env-file、-w、--rm 和 -d 的用法都和 Docker 相同。
    • --name 是 2 到 63 個字元，可用英文字母、數字、_、. 和 -，開頭和結尾都必須是英文字母或數字。
    • --entrypoint "" 會清除映像的 entrypoint，之後要在映像名稱後面給指令。

    GPU¶

    指令 你得到什麼
    docker run --gpus all … 或 --gpus N 容器和你的工作區共用 GPU，不會多用 GPU 配額和 GPU 時數。N 不能超過工作區的 GPU 數。--gpus device=0,1 用索引編號指定 GPU，不能用 UUID。
    docker run --keep --gpus N … 容器另外取得 N 張 GPU，從專案的配額和計畫扣，排程佇列和工作區相同。這些 GPU 會計入 GPU 時數。加上 --keep 時，--gpus 只能給數字。

    沒有 GPU 的工作區用 --gpus all 或 --gpus N 會得到 this workspace has no GPU to share; use --keep --gpus N to allocate one for the container。共用 GPU 的容器和工作區用同一張卡，記憶體也是共用的。

    容器和工作區¶

    容器跟著工作區結束：工作區停止時（刪除、超過閒置上限、超過執行時間上限或暫停），容器也會停止。工作區暫停後恢復，容器不會回來。執行中的容器算活動，有容器在跑，工作區就不會因閒置被停止。

    --keep 讓容器脫離工作區。工作區停止後它繼續執行，當作一般任務計入專案的任務數量限制，也不能共用工作區的 GPU。用 docker stop 停止它。

    結束的容器連同日誌在 docker ps -a 留 24 小時，期間名稱仍被佔用。docker ps -a 列的是你在這個專案、所有工作區啟動的容器。

    因工作區停止而結束的容器顯示 Exited (137)，日誌已經不在，docker logs 會回 can not get logs from container which is dead or marked for removal。

    --rm 在 docker run 顯示結束碼後立刻移除容器。用 -d 啟動的容器，結束後約一分鐘移除。沒用 --rm 時，可以用 docker rm 或 docker container prune 提早移除。

    停止、強制結束與移除¶

    • docker stop 先送 SIGTERM，10 秒後再送 SIGKILL。-t 會接受，但 10 秒是固定的。容器會留在 docker ps -a，顯示 Exited (143) 或 Exited (137)，日誌也還在。
    • docker kill 的流程和 docker stop 一樣：先 SIGTERM，10 秒後 SIGKILL。有處理 SIGTERM 的程式會以 143 或 0 結束，所以結束碼不一定是 137。容器會留在 docker ps -a。docker kill -s HUP（或 USR1、INT 等其他訊號）會經由 shell 送給容器的主程序，所以映像要有 /bin/sh。程式沒處理那個訊號就會忽略。訊號送不出去時，會得到 could not deliver SIGHUP: …。
    • docker rm 移除已結束的容器。docker rm -f 會先強制結束執行中的容器。

    連接埠和瀏覽器¶

    -p 8080:8000 把工作區的 8080 連接埠轉到容器的 8000，在工作區終端機這樣連：

    curl localhost:8080

    連接埠只開在 localhost，其他機器連不到，只支援 TCP。只寫 -p 8000 會挑一個空的連接埠，用 docker port web 查。連接埠已被佔用時，會在容器啟動前失敗並顯示 port is already allocated。按 Ctrl-C 後轉送仍有效，容器結束才停止。

    要在瀏覽器開啟應用程式，從工作區的網址開始（按 開啟）：

    https://<平台網址>/api/v1/ide/proxy/<工作區名稱>/

    再加上 proxy/8080/：

    https://<平台網址>/api/v1/ide/proxy/<工作區名稱>/proxy/8080/

    JupyterLab 和 VS Code 工作區都適用，結尾的斜線要保留。請求到你的應用程式前，平台會先移除 proxy/8080。應用程式如果用 /static/app.js 這種絕對路徑，這些檔案透過這個網址會載不到，請改用相對連結，或把 base path 設成完整網址。

    互動式容器、exec 與複製¶

    docker run -it ubuntu bash
docker exec -it web sh
docker attach web
docker cp ./results.csv web:/tmp/
docker cp web:/var/log/app.log .
    • -it 在容器裡開終端機，依序按 Ctrl-P、Ctrl-Q 可以離開但不停止容器。
    • docker exec 在執行中的容器裡跑指令，可用 -i、-t、-d、-e 和 -w，不能用 -u。-e 的值會放在指令列傳送，可能出現在平台的 API 日誌，密鑰請改用儲存空間裡的檔案傳。
    • docker attach 連上容器的主程序。
    • docker cp 透過 tar 雙向複製，所以映像要有 tar。連結照原樣複製，不會跟隨：不會透過連結寫入，目的地本身是連結也會拒絕。和 Docker 一樣，不會用檔案取代資料夾，或用資料夾取代檔案。
    • exec 或 attach 連線最多維持 24 小時。

    映像¶

    docker build -t myimg .
docker run myimg
docker images

    docker build 會上傳資料夾，在平台上建置，再把映像存進你的專案。FROM 的映像可以來自任何映像倉庫。平台會自動掃描 base image，不需要先核准。-f 可以指定任何路徑的 Dockerfile，--build-arg KEY=VALUE 的用法和 Docker 相同。建置完成後，單純的名稱如 myimg 或 myimg:v2（沒有映像倉庫、沒有 /）會啟動你建置的映像，而不是同名的公開映像。docker images 列出專案的建置結果。資料夾裡的 .dockerignore 用法和 Docker 相同，Dockerfile 一律會送出。

    和 cscc-cli build 一樣，建置需要專案管理者（Project Manager）以上的角色，專案也要開啟 映像建置權限。

    容器啟動前，平台會檢查每個映像的安全性。檢查期間 docker run 會顯示 Waiting: image security check…。平日上班時段平台會限制網際網路的下載速度，大型映像第一次啟動可能慢很多。docker pull 只會印出提醒，因為平台會在容器啟動時取得映像。

    限制¶

    限制 內容
    大小 每個容器預設 1 個 CPU 和 4 GiB 記憶體
    專案配額 容器的 CPU、記憶體和 GPU 都計入專案配額，GPU 也計入 GPU 時數。共用工作區 GPU 的容器不會多算。
    每個工作區的容器數 執行中或等待中最多 50 個。--keep 容器另有每位專案成員 50 個的限制。超過時 docker run 會失敗並顯示 too many containers。
    同時執行 你在一個專案裡最多是專案設定的每位成員同時執行任務數上限的兩倍（專案沒設定時是 20 個），工作區和它的容器一起算。還沒移除的已結束容器計入 60 個的總量。
    任務數量限制 跟著工作區執行的容器不計入專案的同時執行任務數。--keep 容器會計入。
    已結束的容器 結束後連同日誌留在 docker ps -a 24 小時。--rm、docker rm 和 docker container prune 可以更早移除。
    環境變數的值 -e 的值直接交給容器，專案裡的其他成員看不到。

    暫停

    平台為了釋放 GPU 而暫停工作區時（見概念與角色的「暫停而不是停止」），會先停止工作區的容器，暫停照常進行。工作區恢復後，容器不會回來。

    指令¶

    指令 作用
    docker run 啟動容器。可用 -d -i -t -e --env-file -v --mount -w -u --cpus -m --gpus --name --rm --keep --entrypoint -p --shm-size。--pull 和 --platform 會接受，只印出一則說明。
    docker exec、attach、cp 在執行中的容器裡執行指令、連上容器，或和容器互相複製檔案
    docker ps [-a] [-q] [--format] [-f] 列出你在這個專案裡、從所有工作區啟動的容器。-a 會加上最近 24 小時內結束的容器。
    docker logs [-f] [--tail N] [-t] [--since] 顯示容器的輸出
    docker stop [-t N]、kill [-s SIGNAL]、rm [-f] 停止（先 SIGTERM，10 秒後 SIGKILL）、送出訊號，或移除容器
    docker wait、inspect、port 印出結束碼、詳細資料或轉送的連接埠
    docker build、images、pull 建置映像、列出專案的建置結果、印出提醒
    docker container ls、rm、prune、docker system prune 較長的寫法。prune 只移除已結束的容器。
    docker info、version 顯示你的專案、排程佇列和 GPU

    下列指令不存在，每個都會印出一行說明該改用什麼：

    不支援 原因
    compose、network、volume 沒有多容器執行環境、沒有自訂網路，也沒有具名 volume。用 docker run -d 啟動每個服務，並從儲存空間掛載資料夾。
    push、commit、save、load、tag、rmi 映像留在你的專案裡。用 docker build -t NAME:TAG。
    start、restart、pause、unpause 已結束的容器不能再啟動，請執行新的容器。
    stats、top、events 平台不收集這些資料。用 docker exec NAME top，或 docker ps 和 docker wait。
    login 工作區已經登入。
    -P、--network、--privileged、--cap-add、--device、--restart、--ipc、--pid、UDP 連接埠、exec -u 容器共用平台的網路、彼此隔離，不會以特權執行，也不能新增 Linux capability。

    疑難排解¶

    你看到的 代表什麼
    Waiting: image security check… 一直顯示 容器還沒啟動。新映像要等安全檢查，佇列忙碌時要等資源。讓指令開著，或加 -d 執行，再用 docker logs -f 追蹤。
    結束碼 125 容器根本沒啟動：取不到映像（例如 pull access denied）、映像被安全檢查擋下（原因會寫 blocked by the platform），或選項無效。原因會印在結束碼上方，容器會自動移除。
    結束碼 126 或 127 映像裡的指令無法執行（126）或不存在（127）。檢查映像的 ENTRYPOINT 和你的指令。
    結束碼 143 docker stop、docker kill 或 Ctrl-C 用 SIGTERM 結束了容器。
    結束碼 137 容器被強制結束。可能是記憶體不足（docker inspect NAME 會顯示 "OOMKilled": true，請調高 -m）、它 10 秒內都沒理會 SIGTERM，或它的工作區停止了。
    容器一啟動就出現 Permission denied 或 Operation not permitted，例如 nginx 這類映像 映像的主程序需要 root，而映像沒有宣告數字 USER，所以容器以使用者 1000 執行。在允許 root 容器的專案加上 -u 0，或改用不需要 root 的映像版本，例如 nginxinc/nginx-unprivileged。
    port is already allocated 工作區的這個連接埠已被其他程式或容器佔用。換一個主機連接埠，並檢查 docker ps。
    Conflict. The container name "/web" is already in use 同名的容器還在，最近 24 小時內結束的也算。執行 docker rm web，或換一個名稱。
    Invalid container name 用 2 到 63 個英文字母、數字、_、. 和 -，開頭和結尾都要是英文字母或數字。
    can not get logs from container which is dead or marked for removal 容器的日誌已經不在：它的工作區停止了，或它已被移除。
    this workspace has no GPU to share 工作區沒有 GPU。用 --keep --gpus N，或啟動有 GPU 的工作區。
    is outside your workspace storage 或 named volumes are not supported 請掛載家目錄或群組儲存空間底下的資料夾。
    invalid or expired workspace token 重試一次。持續發生的話，刪除工作區再啟動新的。
    restart your workspace for full docker support 這個工作區是更新前啟動的。刪除它再啟動新的。

    Token 管理¶

    列出你有效的 API token：

    cscc-cli tokens list

    用 token ID 撤銷 token：

    cscc-cli tokens revoke <token-id>

    登出這台電腦：

    cscc-cli logout

    登出會撤銷你正在用的 token，並從設定檔移除。你手動設定的憑證選項會保留。

    預設值¶

    設定 預設值 說明
    Token 有效期 90 天 到期後請重新建立一個
    每人有效 token 上限 20 達到上限時，請先撤銷不再使用的 token
    登入失敗鎖定次數 5 儀表板和 CLI 一起算
    鎖定時間 15 分鐘 等它解除，或請管理員解鎖

    管理員可以調整這些數值。
