    用兩張 GPU 跑 14B 模型的 vLLM 服務¶

    Qwen2.5-14B-Instruct 是很好用的開源模型，但用 16 位元精度載入，光權重就要 28 GB 左右。RTX 5090 只有 32 GB，放完權重，就沒剩空間給 KV cache（每段對話都要用到的那塊記憶體）。張量平行（tensor parallelism）把每一層拆到兩張 GPU 上，每張卡只放一半權重，剩下的記憶體都能拿來當 cache。下面這次實測，vLLM 在兩張 RTX 5090 上同時處理 64 個請求，每秒產生 2,625 個 token；只用一張卡的話，服務根本起不來。

    這篇從工作區啟動模型服務，再用 OpenAI 的 Python 套件呼叫它。跟著做完，你會有：

    • 存在群組儲存空間的模型權重，下載一次，之後每次開服務都能重複用
    • 一個跑在兩張 GPU 上、介面和 OpenAI API 相容的 vLLM 服務
    • 單一請求和同時 64 個請求的實測速度，還有一張 GPU 為什麼跑不起來的實測結果

    文中的指令和輸出，都是 2026-10-04 在平台上實際跑出來的。

    事前準備¶

    • 專案裡有能用 2 張 GPU 的佇列，並綁定一個還有約 35 GB 空間的群組儲存空間（見儲存空間）
    • 在這個專案開一個工作區，勾選那個群組儲存空間；工作區本身不需要 GPU
    • 大約 30 分鐘，大部分花在第一次下載

    會用到什麼¶

    元件 在哪裡跑 做什麼
    工作區 平台 你的終端機：下載模型、啟動和呼叫服務
    vLLM 服務 獨立的工作，佔 2 張 GPU 每張 GPU 載入每一層的一半，回應 OpenAI API 呼叫
    models/ 群組儲存空間 29.5 GB 的權重，所有服務和實驗室成員共用

    步驟 1：把模型下載到群組儲存空間¶

    先用 df -h /home/<你的使用者名稱> /mnt/shared/<儲存空間名稱> 看剩多少空間。這次個人儲存空間只有 10 GiB，放不下這個模型，所以放到群組儲存空間，實驗室其他人也能直接用。在工作區的終端機執行：

    pip install --user "huggingface_hub[hf_xet]==1.32.0"
export PATH=$HOME/.local/bin:$PATH
hf download Qwen/Qwen2.5-14B-Instruct --local-dir /mnt/shared/<儲存空間名稱>/models/Qwen2.5-14B-Instruct

    模型總共 29.5 GB，分成八個檔案。工作區中途重啟也沒關係，再跑一次同樣的指令，會從中斷的地方接著下載。

    步驟 2：在兩張 GPU 上啟動服務¶

    工作區裡有 docker 指令，可以在工作區旁邊啟動容器（見在 IDE 裡使用 docker）：

    docker run -d --keep --name qwen14b --gpus 2 --cpus 8 -m 48g --shm-size 8g \
  -p 8000:8000 \
  -v /mnt/shared/<儲存空間名稱>/models:/models:ro \
  -e HOME=/tmp \
  vllm/vllm-openai:v0.30.0 \
  --model /models/Qwen2.5-14B-Instruct --served-model-name qwen2.5-14b \
  --tensor-parallel-size 2 --max-model-len 8192

    ① --keep --gpus 2 從專案配額另外拿兩張 GPU 給容器。工作區本身沒有 GPU，沒有卡可以分給容器。 ② -p 8000:8000 把 API 開在工作區裡的 127.0.0.1:8000。 ③ -v …:/models:ro 用唯讀方式掛權重，服務不可能弄壞共用的那份。 ④ -e HOME=/tmp 讓 vLLM 把編譯快取放在容器裡，不寫到家目錄。 ⑤ --tensor-parallel-size 2 把每一層拆到兩張 GPU 上。

    用 docker logs -f qwen14b 看啟動過程，重點是這幾行：

    Model loading took 13.93 GiB memory and 47.540906 seconds
GPU KV cache size: 149,488 tokens, Maximum concurrency for 8,192 tokens per request: 18.25x
init engine (profile, create kv cache, warmup model) took 176.75 s (compilation: 20.35 s)
Application startup complete.

    每張 GPU 放 13.93 GiB，剛好是一半的權重。其餘記憶體拿來當 cache，放得下 149,488 個 token，夠 18 段最長的對話同時跑。這次從 docker run 到服務可用花了 8 分鐘，其中 2 分 42 秒是映像的安全檢查和第一次下載，之後再啟動就不用等這段。

JOB261004001569   vllm/vllm-openai:v0.30.0   "--model /models/Qwe…"   8 minutes ago   Up 5 minutes   127.0.0.1:8000->8000/tcp   qwen14b

    步驟 3：呼叫模型¶

    服務的介面和 OpenAI API 一樣，官方套件只要改 base URL 就能用。在工作區存成 bench.py：

    """Ask the vLLM server one question, then measure throughput under load.

Usage: python bench.py [concurrent requests]
"""
import asyncio
import sys
import time

from openai import AsyncOpenAI

client = AsyncOpenAI(base_url="http://127.0.0.1:8000/v1", api_key="unused")
MODEL = "qwen2.5-14b"


async def ask(prompt, max_tokens=256):
    r = await client.chat.completions.create(
        model=MODEL, messages=[{"role": "user", "content": prompt}],
        max_tokens=max_tokens, temperature=0.7)
    return r.choices[0].message.content, r.usage.completion_tokens


async def main(n):
    start = time.time()
    answer, tokens = await ask("用三句話解釋什麼是 tensor parallelism。")
    print(f"{answer}\n-- {tokens} tokens in {time.time() - start:.2f}s\n")

    prompts = [f"Write a short story about GPU number {i}." for i in range(n)]
    start = time.time()
    results = await asyncio.gather(*(ask(p) for p in prompts))
    seconds = time.time() - start
    total = sum(t for _, t in results)
    print(f"{n} concurrent requests: {total} tokens in {seconds:.1f}s = {total / seconds:,.0f} tokens/s")


asyncio.run(main(int(sys.argv[1]) if len(sys.argv) > 1 else 64))

    pip install --user openai==2.8.1
python bench.py 1
python bench.py 64

    Tensor parallelism是一種在深度學習模型訓練中分發計算和數據的方法，它將大型張量（多維數組）分割成更小的部分，並在不同的處理器或設備上並行處理這些部分。這種技術可以加速模型的訓練過程並允許使用更大的模型和數據集。
-- 68 tokens in 1.01s

1 concurrent requests: 256 tokens in 2.9s = 88 tokens/s
…
64 concurrent requests: 16384 tokens in 6.2s = 2,625 tokens/s

    結果¶

    設定 結果
    2 張 GPU，1 個請求 每秒 88 個 token
    2 張 GPU，同時 64 個請求 每秒 2,625 個 token
    1 張 GPU 啟動失敗：No available memory for the cache blocks
    • 一次只送一個請求，GPU 大部分時間都閒著。vLLM 會把同時進來的請求合在一起算，所以同時送 64 個請求時，每秒產生的 token 數是單一請求的 30 倍。
    • 只用一張 GPU 時，同樣的指令改成 --gpus 1、拿掉 --tensor-parallel-size，載入 27.57 GiB 權重後就停了，已經沒有記憶體可以給 KV cache。在這種卡上，這個模型一定要兩張 GPU 才跑得起來。

    步驟 4：停止服務¶

    加了 --keep 的容器在工作區停掉後還會繼續佔著 GPU，而且算進專案的工作數上限和 GPU 時數。用完就刪掉：

    docker rm -f qwen14b

    權重還留在群組儲存空間，下次啟動不用再下載。

    成果¶

    你做出了一個和 OpenAI API 相容的 14B 模型服務，拆在兩張 GPU 上跑，權重只存一份給整個實驗室用。接下來可以：

    • 在工作區裡，把 OpenAI 套件、LangChain 或 LlamaIndex 的 API 位址指到 http://127.0.0.1:8000/v1。
    • 方案允許四張 GPU 的話，用 --gpus 4 --tensor-parallel-size 4 試更大的模型。
    • 只拿得到一張 GPU 時，改用量化過的版本（例如 AWQ）。
    • vLLM 版本固定下來；換新的 tag，第一次啟動要等它的安全檢查。
