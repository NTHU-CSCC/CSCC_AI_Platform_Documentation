    用自己的 Ray 映像，在多台機器的 GPU 上跑同一個 NCCL 工作¶

    vLLM 的 data parallel 和大部分多 GPU 的 PyTorch 程式，每個 Ray worker 上都要有 PyTorch 和 NCCL，需要的 GPU 也常常超過一台機器的張數。平台的 Ray 映像沒有 PyTorch。加上 X-CSCC-Image 標頭，Ray 工作階段就會改用你自己建的映像，worker 也能分散在不同機器上。下面這次實測，三張 RTX 5090 分在兩台機器，組成同一個 NCCL group，all-reduce 的 bus bandwidth 是 0.74 GB/s。

    這篇先建一個含 PyTorch 和 vLLM 的 Ray 映像，再從筆電送出跨機器的 NCCL all-reduce。跟著做完，你會有：

    • 一個放在專案裡、Ray 工作階段能用的映像
    • 一個 worker 跑在不同機器上、都用這個映像的 Ray 工作階段
    • 實際量到的 worker 之間 NCCL 頻寬

    文中的指令和輸出，都是 2026-10-06 在平台上實際跑出來的。

    事前準備¶

    • 連得上 VPN，在某個開了 映像建置權限 的專案裡有 管理者 角色，也已經有 API token（在設定建立）
    • 從設定 → 安全性 → 下載拿到的 cscc-cli 和 根憑證
    • 筆電裝了 Python 3.10 以上
    • 專案裡有一個能用 3 張以上 GPU 的佇列
    • 大約 45 分鐘，大部分是第一次建置映像

    會用到什麼¶

    元件 在哪裡跑 做什麼
    ray-vllm 映像 專案的映像倉庫 Ray 2.58.0、PyTorch 2.9、vLLM 0.11.2
    ray 指令 你的筆電 上傳資料夾、送出工作、把輸出印回來
    Ray 工作階段 平台 head 和 worker 都跑你的映像，一個 worker 一張 GPU
    allreduce.py worker 一張 GPU 一個 NCCL rank，量 all-reduce 的時間

    步驟 1：寫 Dockerfile¶

    在空資料夾裡存成 Dockerfile：

    FROM rayproject/ray:2.58.0-py311-gpu

USER root
RUN apt-get update -y && \
    apt-get install -y --no-install-recommends ibverbs-providers && \
    rm -rf /var/lib/apt/lists/*

USER ray
RUN pip install --no-cache-dir "vllm==0.11.2" "ray[default]==2.58.0"

    ① Ray 一定要是 2.58.0，跟平台的 Ray 工作階段同一版。 ② 最後要切回 USER ray。worker 以 UID 1000 執行，在這個基底映像裡就是 ray。 ③ 有 ibverbs-providers，管理員幫專案開啟 RDMA 網路後，NCCL 就能直接用；沒有的話 NCCL 只會走 TCP。

    建置失敗時：

    錯誤訊息 解法
    external Dockerfile frontend is not allowed 刪掉 # syntax= 那行
    must be a regular file or directory 資料夾裡的符號連結換成實際檔案
    Dockerfile RUN instruction uses a disallowed flag 把 RUN 裡的 --mount=type=cache、secret 或 ssh 拿掉

    步驟 2：建置映像¶

    cscc-cli build --project <project id> --name ray-vllm --tag 2.58.0-vllm0.11.2 .

    建置排入佇列時，cscc-cli 會印出映像的目的地。這次是：

    Destination: 192.168.110.1:30003/p26000001/ray-vllm:2.58.0-vllm0.11.2

    這次建置花了約 20 分鐘，大部分時間在下載 PyTorch 和 vLLM，映像約 11 GB。基底映像和套件不變時，重新建置會沿用快取的 layer。

    步驟 3：設定筆電¶

    裝好 Ray、信任平台的 根憑證，再把映像寫進標頭。每一行的意思見提交工作。

    pip install "ray[default]==2.58.0"
export REQUESTS_CA_BUNDLE=~/Downloads/cscc-root-ca.pem
export SSL_CERT_FILE=~/Downloads/cscc-root-ca.pem
export RAY_JOB_HEADERS='{"Authorization":"Bearer cscc_xxx","X-CSCC-GPUs":"3","X-CSCC-Queue":"<queue>","X-CSCC-Image":"<步驟 2 的目的地>"}'
export RAY_ADDRESS=https://api.cscc.nthu.edu.tw/api/v1/projects/<project id>/ray

    要用 8 張 GPU，就把標頭改成 "X-CSCC-GPUs":"8"，執行時加 --gpus 8。

    步驟 4：寫 all-reduce 測試¶

    在另一個空資料夾裡存成 allreduce.py：

    """Measure NCCL all-reduce bandwidth across GPU workers on several machines."""
import argparse
import os
import socket
import time

import ray


@ray.remote(num_gpus=1)
class Rank:
    def endpoint(self):
        with socket.socket() as s:
            s.bind(("", 0))
            port = s.getsockname()[1]
        return ray.util.get_node_ip_address(), port

    def run(self, rank, world, addr, port, mib, iters):
        import torch
        import torch.distributed as dist

        os.environ.update(MASTER_ADDR=addr, MASTER_PORT=str(port))
        dist.init_process_group("nccl", rank=rank, world_size=world)
        x = torch.ones(mib * 1024 * 1024 // 4, device="cuda")
        for _ in range(3):
            dist.all_reduce(x)
        torch.cuda.synchronize()
        start = time.perf_counter()
        for _ in range(iters):
            dist.all_reduce(x)
        torch.cuda.synchronize()
        seconds = (time.perf_counter() - start) / iters
        dist.destroy_process_group()
        with open("/proc/sys/kernel/random/boot_id") as f:
            machine = f.read().strip()[:8]
        busbw = x.numel() * 4 * 2 * (world - 1) / world / seconds / 1e9
        return rank, machine, torch.cuda.get_device_name(), seconds * 1e3, busbw


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--gpus", type=int, required=True)
    parser.add_argument("--mib", type=int, default=256)
    parser.add_argument("--iters", type=int, default=20)
    args = parser.parse_args()

    ranks = [Rank.remote() for _ in range(args.gpus)]
    addr, port = ray.get(ranks[0].endpoint.remote())
    rows = ray.get([r.run.remote(i, args.gpus, addr, port, args.mib, args.iters)
                    for i, r in enumerate(ranks)])
    for rank, machine, gpu, ms, busbw in sorted(rows):
        print(f"rank {rank}  machine {machine}  {gpu}  {ms:7.1f} ms  {busbw:5.2f} GB/s")
    print(f"machines: {len({r[1] for r in rows})}, GPUs: {len(rows)}, "
          f"all-reduce {args.mib} MiB bus bandwidth: {min(r[4] for r in rows):.2f} GB/s")

    ① @ray.remote(num_gpus=1)：一張 GPU 一個 actor，Ray 就會替每個 rank 開一個 worker。 ② rank 0 的位址加上一個沒被佔用的 port，當作 NCCL 的集合點。 ③ 同一台機器上的 worker 讀到的 boot_id 相同，數有幾種不同的值，就知道用了幾台機器。

    步驟 5：送出工作¶

    ray job submit --working-dir . \
  --runtime-env-json '{"env_vars":{"NCCL_DEBUG":"INFO","NCCL_DEBUG_SUBSYS":"INIT,NET"}}' \
  -- python allreduce.py --gpus 3

    新映像的第一個工作，要等每台機器各下載一次映像，這次每台大約 2 分鐘。這段時間裡 ray job submit 可能提早結束：

    訊息 發生什麼事 怎麼做
    Failed to connect to Ray at address 叢集 2 分鐘內沒準備好 再執行一次同一個指令
    WebSocket connection closed unexpectedly with close code 1006 工作已經收下，只是 worker 啟動時輸出串流斷了 工作會繼續跑，用 ray job logs <job id> 和 ray job status <job id> 追蹤

    這次輸出串流在 2 分 23 秒時斷掉，工作在送出後 173 秒成功。worker 已經起來的叢集，同樣的工作只要 24 秒。

    步驟 6：看結果¶

    rank 0  machine 513bdbb4  NVIDIA GeForce RTX 5090    480.6 ms   0.74 GB/s
rank 1  machine 513bdbb4  NVIDIA GeForce RTX 5090    480.6 ms   0.74 GB/s
rank 2  machine 9e293410  NVIDIA GeForce RTX 5090    480.6 ms   0.74 GB/s
machines: 2, GPUs: 3, all-reduce 256 MiB bus bandwidth: 0.74 GB/s

    ray job status raysubmit_8X3jDzUBBWqFXkw3 回報 SUCCEEDED。

    NCCL 的訊息看得出 rank 之間怎麼傳資料：

    NCCL INFO NCCL version 2.27.5+cuda12.9
NCCL INFO NET/IB : No device found.
NCCL INFO Channel 00/0 : 0[0] -> 1[0] [receive] via NET/Socket/0
    • 兩個 rank 在同一台機器，第三個在另一台，三個都在同一個 NCCL group 裡。
    • via NET/Socket 代表走 TCP。同一台機器上的 rank 也一樣，因為每個 worker 是分開的。
    • 256 MiB 的 bus bandwidth 是 0.74 GB/s，一次 all-reduce 花 0.48 秒。幾次測下來介於 0.58 到 0.74 GB/s，設 NCCL_SOCKET_NTHREADS=4、NCCL_NSOCKS_PERTHREAD=4 也沒有變快，用預設值就好。

    每個 worker 會保留一張 GPU 和 16 GiB 記憶體。之前試過要 4 張 GPU，第四個 worker 一直在等：唯一還有空 GPU 的機器，記憶體不夠，程式也跟著卡住。送出前先到儀表板首頁的 GPU Cluster Status 看還有幾張空的 GPU。想少用幾張，就把 --gpus 調小；要調低 X-CSCC-GPUs，得先結束工作階段。

    步驟 7：結束工作階段¶

    想馬上把 GPU 還回去，打開專案的 Ray 分頁，在 Ray 工作階段 按 結束工作階段。

    成果¶

    現在你有一個用自己映像、跨多台機器 GPU 的 Ray 工作階段，也知道 NCCL 的基準頻寬。換成你自己的工作：

    • 套件（PyTorch、vLLM）放進映像，程式碼用 --working-dir 上傳，改程式就不必重新建置。照 allreduce.py 的做法，一張 GPU 開一個 rank。
    • 在 Ray 上跑 vLLM 的 data parallel 時，模型權重放在群組儲存空間（/mnt/shared/<儲存空間名稱>/...），每個 worker 才讀得到同一個路徑。
    • X-CSCC-Image 用 tag 指定映像，重新建置就換新 tag；執行中的工作階段會一直用它開起來時的映像。
    • worker 之間走 TCP，抓 0.6 到 0.7 GB/s：一次 256 MiB 的 all-reduce 大約半秒。每一步都要交換這麼多資料的工作，時間大多會花在網路上。
